# Dropbox and Google Drive administrator consent

These are copy destinations only. Create a disabled storage connection with `config: {clientId, rootPath?}` and write-only `credentials: {clientSecret}`. For any endpoint below use the canonical HTTPS portal. Portal login stays local and unchanged; a provider grant can never sign in to ReadyPackets.

| Provider | App registration and destination | Egress preset |
|---|---|---|
| Dropbox (`dropbox`) | Create a scoped **App Folder** app. Enable `files.metadata.read` and `files.content.write`. Map the Dropbox app key to `clientId`; `rootPath` is a relative path within the app folder. Leaving it blank uses the app folder directly. See [Dropbox OAuth](https://docs.dropboxapi.com/dropbox-api/docs/oauth). | `dropbox`: `api.dropboxapi.com`, `content.dropboxapi.com` |
| Google Drive (`google_drive`) | Enable the Drive API and register a **Web application** OAuth client on the desired consent screen. The portal requests only [`drive.file`](https://developers.google.com/workspace/drive/api/guides/api-specific-auth). It creates and manages its own folders in the consenting account's My Drive; it does not accept arbitrary existing folders or shared drive IDs. A blank `rootPath` uses the app-created `ReadyPackets` folder. | `google_drive`: `oauth2.googleapis.com`, `www.googleapis.com` |

Use **exactly** the redirect URI shown in the wizard when registering the provider app. Do not register the alias domain or a different environment's URI. After consent, test connectivity and explicitly enable and assign the connection. A connectivity test is read-only and does not prove permission for every write. Do not add either provider solely for portal sign-in.

| HTTP path | Contract |
|---|---|
| `GET /api/storage/oauth/redirect-uri/:provider` | Full admin session with fresh `storage.manage` step-up. Returns `{redirectUri}`. |
| `POST /api/storage/oauth/start` | Canonical origin, normal session-bound CSRF, full admin session and fresh step-up. JSON `{provider,publicId,expectedVersion}`. Returns only `{authorizeUrl}` and sets a dedicated five-minute `Secure`, `HttpOnly`, `SameSite=Lax` binder cookie. Use top-level navigation to `authorizeUrl`. |
| `GET /api/storage/oauth/callback/:provider` | Canonical host and exact callback route, matching state and binder; a portal session cookie is not required on this cross-site hop. Uses the original session for live authorization, including step-up, and validates the same provider, connection and configuration revision before and after exchange. Redirects with `303` to `/admin/storage?oauth=connected` or `/admin/storage?oauth=failed`. |
| `POST /api/storage/oauth/disconnect` | Same authorization and JSON as start. Disables and detaches the grant before attempting provider-side revocation. Returns `{remoteRevoked:boolean}`. If false, remove access directly in the provider's account settings. Existing copies are not deleted. |

Use the normal session CSRF header on both POSTs. The redirects are private and `no-store`; callback query values must not be in access logs. State and the binder are stored as hashes; the expiring verifier and session snapshot are encrypted and removed when claimed or pruned. A refresh token is stored only as an encrypted connection credential; browser responses only expose the safe `oauthConnected` marker. Provider-side access tokens are refreshed as needed and held only in memory. Disconnect uses Dropbox's [access-token revocation operation](https://docs.dropboxapi.com/dropbox-api/api-reference/user-endpoints/auth/token-revoke) or Google's [OAuth revocation endpoint](https://developers.google.com/identity/protocols/oauth2/web-server), sending tokens only in the bearer header or a form body.

Dropbox verifies observed size and the [Dropbox content hash](https://www.dropbox.com/developers/reference/content-hash), not a provider SHA-256. Google Drive verifies the stored object ID, parent, name, private app properties and observed size, plus provider SHA-256 where available. Its folder reservation uses [Drive-generated IDs](https://developers.google.com/workspace/drive/api/guides/create-file) to protect simultaneous copies into a new folder. Treat the app-created hierarchy as managed: renaming, moving or deleting managed folders in Drive can require operator intervention. If a connect result is unconfirmed after a provider issued a grant, inspect or revoke the authorization in the provider console before retrying.
