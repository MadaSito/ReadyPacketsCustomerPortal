# Trash Module (`server/modules/trash`)

Owner: `recovery_ops_engineer` (Increment 09, Decision D2 & D2.8).

## Responsibilities
- Participant registry (`TrashRegistry` / `TrashParticipant` in `./ports.ts`).
- Coordinator (`./service.ts`) orchestrating move-to-trash, restore, resumable row-fenced permanent deletion (`trash_purge_runs` + `trash_purge_run_targets`), per-order unreachable external storage-copy acknowledgment (`finishLeavingExternalCopies`), retention settings (`trash_retention_state` + `platform_settings` with `ownerWriteOnly: true`), and hourly retention clean-up (`trash.retention_cleanup`).
- tRPC router (`export const trashRouter` in `./router.ts`), mounted as `trash: trashRouter` in `server/trpc/root.ts`.

## Security & Concurrency Invariants (D2.8 Final)
1. **Canonical lock order & `RP_DB_POOL_SIZE = 1` safety**: `users -> user_sessions -> orders -> trash_purge_runs -> trash_purge_run_targets -> trash_idempotency_keys`. Zero session advisory locks (`GET_LOCK`) or nested pooled sessions are used anywhere; every operation works on `RP_DB_POOL_SIZE = 1`.
2. **Fail-closed ports, drain gate & manifest**: Missing `identity.trash`, `orders.trash`, `jobAdmin.isDraining(tx)`, `jobAdmin.maintenance.customerAccess(tx)`, or any participant in `EXPECTED_CONTAINER_PARTICIPANTS` fails closed (`503`). Every manifest module must provide a `purge` function unless explicitly listed with a reason in `MANIFEST_NO_DATA_TO_PURGE` (`TRASH_PARTICIPANT_NO_PURGE_HANDLER`).
3. **Permanent per-target run ownership (`trash_purge_run_targets`)**: Every purge claim inserts all expanded targets (root + every group addition including cross-owner reassigned additions + cascaded customer orders + customer) under `UNIQUE(entity_kind, entity_id)`. Competing claims fail `409 PURGE_ALREADY_OWNED`; retries of the primary entity resume the same owning run.
4. **Pure row-locked ownership fence (`TrashPurgeRun.assertCurrentInTx(tx)`)**:
   - Participants call `await run.assertCurrentInTx(tx)` as the first statement of every mutation transaction and in a short transaction before any external provider call. It acquires `FOR SHARE` on `trash_purge_runs` and verifies `status === "running" && fencingToken === token && leaseOwner === owner`, throwing `409 PURGE_FENCE_LOST` otherwise.
   - Takeover locks `trash_purge_runs` `FOR UPDATE` (waiting for any in-flight `FOR SHARE` participant transactions to commit/roll back), requires an expired `lease_expires_at` (or `status === "failed"`), and increments `fencing_token`.
   - Active workers renew `lease_expires_at` by token-CAS between steps and on a background heartbeat timer during long steps, stopping immediately if fence ownership is lost. All coordinator writes verify `(status, fencing_token, lease_owner)` under `FOR UPDATE` in the same transaction.
5. **Scoped per-order unreachable external-copy gate**: `finishLeavingExternalCopies` accepts ONLY the run's current `failed_target_public_id` when `failed_module === "files"` and `error_code === "EXTERNAL_COPIES_UNREACHABLE"`, refuses any sibling order (`409 EXTERNAL_COPIES_ACK_NOT_APPLICABLE`), verifies the typed `RP-...` order number of that exact order, binds the approval to the observed proof set (`leave_external_copies_proof_json`), and records counts strictly for that order.
6. **Atomic reservation <-> claim durability**: `trash_idempotency_keys` writes `status = "claimed"` + `claimed_run_public_id` inside the claim transaction. Reservations linked to incomplete runs are never dropped by 24 h TTL clean-up; a same-fingerprint retry resumes the owning run while any different fingerprint on the same key fails `409 IDEMPOTENCY_KEY_REUSED`.
7. **Row-fenced single-active sweep & persistent progression**: `trash_cleanup_sweeps` enforces single-active execution via `UNIQUE(active_slot)` + `lease_expires_at`. Due candidates are ordered by `(never-tried first, next_retry_at/next_attempt_at ASC, trashed_at ASC, id ASC)` and SQL-filtered by exponential backoff (cap 24 h) across both failed runs (`trash_purge_runs`) and held/refused items (`trash_retention_deferrals`, alerting once via `alerted_at`).
