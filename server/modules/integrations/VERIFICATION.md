## 2. Security Controls & Reviewer Findings Closed

1. **SSRF, DNS Rebinding & Node 22 Socket Pinning (`ipPolicy.ts`, `egress.ts`)**:
   - Blocks loopback, unspecified, link-local, cloud metadata (`169.254.169.254`, `169.254.170.2`, `100.100.100.200`, `fd00:ec2::254`, `metadata.google.internal`), multicast, broadcast, documentation (`2001:db8::/32`, `3fff::/20`), and all IPv4-embedded IPv6 transition prefixes (`::ffff:0:0/96`, SIIT `::ffff:0:0:0/96`, NAT64 `64:ff9b::/96`, 6to4 `2002::/16`, Teredo `2001::/32`), plus octal/hex/decimal/shorthand IPv4 host tricks and IPv6 zone IDs (`%eth0`).
   - Validates **every** A/AAAA record returned by DNS so dual-record rebinding (`[public, 127.0.0.1]`) fails closed.
   - `createPinnedLookup(pinned)` handles both scalar `(ip, family)` and Node 22 `autoSelectFamily` `{ all: true }` `LookupAddress[]` callbacks without touching OS DNS; `https.request` sets `family: pinned.family` and `autoSelectFamily: false`.
   - Enforces a 5 s DNS lookup deadline (`EGRESS_DNS_TIMEOUT`), a total wall-clock HTTP request deadline (`EGRESS_TIMEOUT`), and refuses all HTTP `3xx` redirects (`EGRESS_REDIRECT_REFUSED`).
2. **SMTP Pre-I/O Actor Authorization, Durable Attempt Audit & Persisted/Pre-Dial Port-25 Refusal (`settings.ts`, `smtp.ts`)**:
   - `smtpConfigSettingSchema` rejects `port === 25` during persisted-setting parse (`not_configured` health), `isCompleteSmtpConfig` requires `cfg.port !== 25`, and `buildPinnedTransportOptions` / `send` / `sendTestMessage` enforce `precheckSmtpPortAndTls` (`SMTP_PORT_25_FORBIDDEN`, `failing` health) immediately before dialing so even directly seeded or restored port-25 DB settings never open a DNS lookup or socket.
   - `sendTestMessage` runs a short DB transaction **before** revealing secrets or opening network sockets: re-validates the actor via `identity.sessions.assertCurrent(principal, tx)`, reads SMTP config/secret inside `tx`, and writes a durable `integration.smtp.test_attempted` (`outcome: "attempted"`) audit event. Revoked sessions or unavailable audit stores abort with zero outbound SMTP connection attempts and zero DB locks held across network I/O.
   - Outbox `send()` distinguishes pre-connection errors (`retryable: true`) from post-connection drops without an SMTP status code (`outcome: "unknown"`) so mail workers never auto-duplicate ambiguous deliveries.
3. **Synchronous Analytics JS-Realm Quarantine (`INT-01`) & Clean URL Gate (`consent.tsx`, `client/src/lib/realmTaint.ts`)**:
   - Clarity and PostHog remain disabled by default.
   - Refuses to render or mount Clarity/PostHog whenever `window.location.search !== ""` or `window.location.hash !== ""` so query/fragment tokens on legal URLs can never be read by vendor code.
   - Sets `data-clarity-mask="true"` on `document.documentElement` before mounting the Clarity script tag.
   - Calls `markRealmTainted("clarity")` **synchronously immediately before** appending the `<script>` tag and `markRealmTainted("posthog")` **synchronously immediately before** sending `fetch(...)`. App-root `<RealmTaintBoundary>` and `<TaintedRouteGate>` (`client/src/app/RealmTaint.tsx`) refuse to render any non-public or authenticated DOM in a tainted realm and trigger a full-document navigation (`requestCleanRealm`) instead.
   - Keeps a latched `history.pushState`/`replaceState` guard armed for the lifetime of the tainted document so programmatic SPA navigations to non-public paths or `?search`/`#hash` URLs are refused before `pushState` mutates `window.location` (including repeated attempts while async document replacement is in flight). Browser-driven `popstate`/`hashchange` events fire after the browser updates `window.location`; capture-phase listeners stop router propagation and request a clean realm. Same-origin script/API authority in a vendor-loaded document remains an acknowledged residual outside the React DOM quarantine.
4. **Stripe Hard-Disabled Scaffold (`stripe.ts`, `http.ts`)**:
   - Hard-disabled behind `STRIPE_LEDGER_MUTATION_ENABLED = false as const`. `isOnlinePaymentConfigured()` always returns `false`; `updateConfig({ enabled: true })` fails with `STRIPE_NOT_AVAILABLE_IN_RELEASE`.
   - Signed webhooks verify `Stripe-Signature` over raw bytes, normalize client IP rate-limit keys via `rateLimitAddress(req.ip)`, record inert `ignored` rows + audit notes with `ledgerMutated: false`, and never invoke ledger booking.
5. **Outbound Production Webhooks (`production/**`, `egress.ts`, `authz.ts`, `settings.ts` — `PW-01` through `PW-08`)**:
   - `egress.fetchPinned(..., "webhook", { requireAllowlistRule: true, publicAddressesOnly: true })` evaluates the mandatory `"webhook"` allowlist rule and verifies that **every** resolved DNS record is globally public inside the exact same `evaluateTarget` call that produces the `PinnedEgressTarget` bound to the TLS socket (`autoSelectFamily: false`), preventing split-DNS TOCTOU rebinding.
   - `settings.test` performs dry-run URL + allowlist + public-DNS validation with zero HTTP requests and never projects `normalizedUrl` or secret URL paths/queries.
   - `p101_url`, `p201_url`, and `auth_value` use `defineSecret` with `exportable: false` (`FieldCrypto` AES-256-GCM — excluded from generic Platform `configTransfer` exports even when `includeSecrets: true`).
   - **Zero remote body persistence (`PW-01`)**: `resp.body` is discarded in `handleDeliveryJob`; `response_summary` stores only fixed server-generated status text mapped from `(reasonCode, httpStatus, state)`.
   - **Job-fenced stale reconciliation & claim-fenced finalization (`PW-02`)**: `integrations.production.deliver` runs with `retrySafe: false` and `maxAttempts: 5`, binding each outbox row to `job_public_id`, `active_fencing_token`, and bounded `expires_at` (`created_at + 24h`). Three SQL-filtered stale candidate passes (evaluated **before** `LIMIT 100` with keyset pagination so fresh rows never starve stale rows) consult `services.jobAdmin.reconcileOutboxJob(jobPublicId, tx, { cancelQueued })` under canonical lock order (`job_runs` first -> `integration_production_dispatches` second, rolling back via `CandidateMovedRollback` on state/version/job drift). Live `running_live` and `queued_live` jobs are never touched; expired leases (`settled_unknown`) and expired/canceled dispatches with `attemptCount > 0` transition to explicit `"unknown"` (`PRODUCTION_DELIVERY_INTERRUPTED` / `PRODUCTION_PRIOR_ATTEMPT_UNCERTAIN`, `outcome: "unknown"`, `delivery_uncertain: true`), while never-attempted orphaned/expired `queued` rows (`attemptCount === 0`) transition to `"failed"` (`PRODUCTION_QUEUE_STALLED` / `PRODUCTION_DELIVERY_EXPIRED`), scrubbing `payload_enc = NULL` and resetting `active_fencing_token = 0`. Worker Phase 3 finalization requires matching `(state === "sending", version === claimedVersion, attemptCount === claimedAttempt, activeFencingToken === claimedFencingToken, jobPublicId === job.jobId)` (`PRODUCTION_FENCE_SUPERSEDED` otherwise) and refuses to re-queue if `payload_enc` is `NULL` or `expires_at` has passed. `P201` remains strictly delivered-only, and admin `resend` displays a verify-downstream-first warning while requiring fresh MFA step-up and audit reason.
   - **Pre-send order & destination pinning (`PW-03`, `PW-04`)**: Dispatches record `expected_owner_user_id` and keyed HMAC-SHA-256 `destination_fingerprint` at queue time. Immediately before sending, the worker re-verifies destination/auth/config fingerprint (`DESTINATION_CHANGED`) and live order lock/hold, cancellation, owner identity/status, and packet scope (`ORDER_LOCKED`, `ORDER_CANCELED`, `ORDER_OWNER_CHANGED`, `ORDER_OWNER_INACTIVE`, `ORDER_NOT_FOUND`, `ORDER_SCOPE_CHANGED`), cancelling and scrubbing `payload_enc = NULL` before opening any socket.
   - **Canonical lock order, fail-closed authz & audit hygiene (`PW-05`, `PW-06`, `PW-07`, `PW-08`)**: Order mutations lock `orders` (`forUpdate: true`) **before** `identity.sessions.assertCurrent(principal, tx)`; `authz.ts` fails closed (`ACTOR_UNVERIFIABLE`) if `identity` is absent and checks step-up freshness against post-lock `clock.now()`; `resend_reason` stores controlled codes only (`OPERATOR_RETRY_AFTER_INTERRUPTION`, `OPERATOR_RETRY_AFTER_DEAD_LETTER`, `OPERATOR_RETRY_AFTER_FAILURE`, `OPERATOR_REPLAY_DELIVERED`); `settings.changed` omits `auth_header_name`; default `release_status` is `""`.
   - `P201` requires `phase1ArtifactsConfirmed === true` AND a `delivered` `P101` on the same order, copying `{ customer_id, order_id, run_mode }` verbatim from the delivered `P101` row.
6. **Cross-Model Transaction & Zero-Trust Invariants**:
   - All `db.transaction(...)` blocks pass `tx` to `settings`, `audit.record(..., tx)`, and `identity.sessions.assertCurrent(principal, tx)` — verified non-deadlocking on a `connectionLimit: 1` MySQL pool.
   - `deleteAllowlistRule` writes its durable `integration.egress.rule_deleted` audit record inside the same transaction **before** executing `DELETE`, and rolls back fail-closed if audit persistence fails.

7. **Increment 03 Cloud Egress, Single-Tenant Graph Client, Mail Failover Safety & Self-Only Test Endpoints (`egress.ts`, `egressPresets.ts`, `graph/**`, `smtp.ts`)**:
   - **Honest Local-Fake Disclosure**: Nothing in Increment 03 has been or can be tested against live Microsoft Entra ID, Microsoft Graph, S3, Azure Blob, Dropbox, Google Drive, or external SMTP relays in this sandbox (no live tenant, bucket, or mailbox). All verification uses MariaDB + local HTTPS/DNS/SMTP protocol fakes, and administrators have dedicated `testConnection` and `sendTest` actions that report safe, specific reason codes.
   - **Default-Off Cloud Presets & Bucket/Account Pinning (`egressPresets.ts`, `egress.ts`)**: All 9 presets ship disabled (`enabled: false`). Cloud purposes enforce `requireAllowlistRule: true` and `publicAddressesOnly: true`. Parameterized S3 (`bucket` + `region`) and Azure Blob (`accountName`) presets derive narrow host rules rather than broad multi-tenant wildcards. Streaming `Readable` uploads require explicit `contentLength` (`EGRESS_STREAM_LENGTH_REQUIRED`) and abort fail-closed on byte mismatch (`EGRESS_STREAM_LENGTH_MISMATCH`). Google Drive resumable `PUT` permits HTTP `308` only when `acceptUploadIncomplete: true` and strips `Location` headers.
   - **Single-Tenant Graph Client, Upload-Session Guardrails & `beforeSend` Fencing (`graph/client.ts`, `graph/tokenCache.ts`, `egress.ts` — `G-02`)**: Rejects `common`, `organizations`, and `consumers` (`GRAPH_COMMON_TENANT_FORBIDDEN`), requiring canonical Entra GUIDs; caches tokens in memory only (`expires_in - 60s`, single-flight coalesced, invalidated on config/secret change, never logged). `uploadSessionChunk` routes through `"graph_upload"` without `Authorization` headers, enforces strict `*.sharepoint.com` / `*.1drv.com` lineage (`EGRESS_HOST_LINEAGE_MISMATCH`), and strips capability query strings from errors/logs/audits. `beforeSend` runs after token acquisition, allowlist evaluation, DNS pinning, and body validation, immediately before `httpsRequester` opens a wire socket.
   - **Fail-Closed Mail Outcome Classification & Shared Sender Authority (`smtp.ts`, `graph/service.ts` — Decision 8, `B-01`, `B-03`)**: `smtp.send()` honors `input.sender` (`fromAddress`, `fromName`, `replyTo`) while `smtp.getConfig()` reads `"jobs.mail.sender"` directly from `SettingsStore` (avoiding `jobAdmin` recursion), and classifies ambiguous post-connect socket drops without explicit pre-DATA command attribution as `outcome: "unknown"`. `graphMailTransport.send()` treats the shared/Jobs `message.sender` as authoritative (enforcing optional `graph.config.senderMailbox` as an allowlist constraint via `GRAPH_SENDER_MAILBOX_MISMATCH`), marks only HTTP `202` on `POST /users/{sender}/sendMail` as `accepted`, classifies `4xx` rejections (`400`/`401`/`403`/`404`) as explicit `rejected`, and classifies `429`/`5xx`/timeouts/unexpected `2xx` as `unknown` so failover never duplicates ambiguous sends.
   - **Self-Only Test Mail (`smtp.sendTest`, `graph.sendTest`)**: Resolves the signed-in administrator's email inside the pre-I/O authorization transaction (`getUser(principal.userId, { tx })`) and rejects any `toAddress` differing from that administrator's email (`TEST_RECIPIENT_SELF_ONLY`).
