Rate limiting first uses a bounded process-local address pre-gate and then database-persisted fixed-duration windows per category. Durable subject slots are 18-bit HMAC outputs keyed with a domain-separated HKDF subkey; the first rollout changes the mapping, so deploy it together across replicas. The theoretical cap is 262,144 counters per category; active collisions share a budget and can cause conservative denials, never acceptance past a shared cap. No raw subject is stored. Worker cleanup deletes at most 20,000 expired rows per minute; expiry resets admission even if cleanup is unavailable. Only standard browsing fails open when durable limiter storage fails, with a bounded operational alert. Browser-origin and CSRF denial events are sampled best-effort notes, not synchronous durable audit writes. This is not a substitute for proxy connection, bandwidth and concurrency limits. Shared installation replicas require synchronized clocks and deployment tests.

The application intentionally ignores forwarded Host. The reverse proxy must preserve canonical Host, replace forwarded client metadata at its trust boundary, and keep the Node listener private. Port authority is exact outside the preview profile and eligible local probes. HSTS is origin-only, without `includeSubDomains` or preload; avoid forwarding a second app copy when the edge emits HSTS.

Preview permits an opaque sandbox or changing proxy host, with `Access-Control-Allow-Origin: *` and no ambient cookie authority. Disable this profile outside an isolated synthetic demo. Production browser sessions are Secure Strict host-only cookies, while the configured plain-HTTP local development profile uses visibly distinct unprefixed cookie names.

## Increment 07 ingress

- **ACS path and envelope:** `tests/http/app.test.ts` verifies no session lookup or cookie, exact-path and alias refusals, URL-encoded form requirement, 256 KiB and field-count limits, compression refusal, and sign-in ban and durable budget. A separate case exercises the default Identity adapter with a synthetic service: opaque form fields are not logged, RelayState is discarded, and malformed fields pass no assertion to the audited refusal path. Identity exercises real signed assertion validation and replay separately.
- **Stripe country rule:** the same suite runs the real Protection evaluator against isolated HTTP requests. Only the literal Stripe POST bypasses the built-in country allow-list. Country denies, custom country rules, explicit IP denies, ordinary rate and byte limits, and other paths/methods are covered. The signature verifier is tested separately by Payments.
- **Deployment gates:** `scripts/ci/release-migrations.test.ts` exercises the 0007 bundle and exact-once journal assertion with fixtures. The native and Compose smoke suites are the deployed checks for plain HTTP and alias SAML refusal, ACS envelope limits, and the installed SQL digest; the native upgrade matrix also checks a seeded pre-0007 database and unchanged order workflow pins. Running these smoke suites requires installed proxy, database and portal services.
- **Playback:** Nginx disables synthetic ranges, compression, caching and response buffering on the grant path; Caddy preserves the upstream response with a short flush interval and no response buffering or transport compression. Files tests cover grant and range behavior. This is not an installed-proxy playback or Entra tenant sign-off.
- **Native ZIP form:** `tests/http/app.test.ts` covers canonical Origin, full-session and cookie-bound CSRF, body limits, preview refusal, exact-path handling, secret-free logs and unchanged header-CSRF JSON. Browser-native attachment behavior remains a deployed-browser check.
