# HTTP security verification

The H-1/H-2 check used the Node 22 wrapper, Vitest/Supertest, jsdom, and isolated MySQL. Single-file `scripts/dev/test.sh` runs passed: `tests/http/app.test.ts` (20 tests), `tests/http/rateLimiter.test.ts` (4), and `tests/http/sessionTransport.test.ts` (2). The runner emitted a shared Vitest configuration warning about redundant JSX transformation options without failing.

Rate limiting first uses a bounded process-local address pre-gate and then database-persisted fixed-duration windows per category. Durable subject slots are 18-bit HMAC outputs keyed with a domain-separated HKDF subkey; the first rollout changes the mapping, so deploy it together across replicas. The theoretical cap is 262,144 counters per category; active collisions share a budget and can cause conservative denials, never acceptance past a shared cap. No raw subject is stored. Worker cleanup deletes at most 20,000 expired rows per minute; expiry resets admission even if cleanup is unavailable. Only standard browsing fails open when durable limiter storage fails, with a bounded operational alert. Browser-origin and CSRF denial events are sampled best-effort notes, not synchronous durable audit writes. This is not a substitute for proxy connection, bandwidth and concurrency limits. Shared installation replicas require synchronized clocks and deployment tests.

The application intentionally ignores forwarded Host. The reverse proxy must preserve canonical Host, replace forwarded client metadata at its trust boundary, and keep the Node listener private. Port authority is exact outside the preview profile and eligible local probes. HSTS is origin-only, without `includeSubDomains` or preload; avoid forwarding a second app copy when the edge emits HSTS.

Preview permits an opaque sandbox or changing proxy host, with `Access-Control-Allow-Origin: *` and no ambient cookie authority. Disable this profile outside an isolated synthetic demo. Production browser sessions are Secure Strict host-only cookies, while the configured plain-HTTP local development profile uses visibly distinct unprefixed cookie names.
