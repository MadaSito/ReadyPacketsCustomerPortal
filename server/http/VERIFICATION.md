Rate limiting intentionally uses database-persisted fixed-duration windows of the first admitted request, independent per category and a deterministic 18-bit subject slot. The theoretical hard cap is 262,144 counters per category; active collisions share a budget and can cause conservative denials, never acceptance past a shared cap. No raw subject is stored. Worker cleanup deletes at most 20,000 expired rows per minute; expiry resets admission even if cleanup is unavailable. Only standard browsing fails open when rate-limit storage fails, with a bounded operational alert. This is not a substitute for proxy connection, bandwidth and concurrency limits; CSRF denials occur before app rate limiting and still attempt a durable audit. Shared installation replicas require synchronized clocks and deployment tests.

The application intentionally ignores forwarded Host. The reverse proxy must preserve canonical Host, replace forwarded client metadata at its trust boundary, and keep the Node listener private. Port authority is exact outside the preview profile and eligible local probes. HSTS is origin-only, without `includeSubDomains` or preload; avoid forwarding a second app copy when the edge emits HSTS.

Preview permits an opaque sandbox or changing proxy host, with `Access-Control-Allow-Origin: *` and no ambient cookie authority. Disable this profile outside an isolated synthetic demo. Production browser sessions are Secure Strict host-only cookies, while the configured plain-HTTP local development profile uses visibly distinct unprefixed cookie names.
