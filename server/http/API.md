# HTTP security API

- `createApp(services: Services, options?: AppOptions): Express` assembles the application. `AppOptions.staticDir?: string` is the prebuilt client root; no directory means API-only.
- `GET /healthz` is liveness. `GET /readyz` is readiness (database, schema and aggregate platform health). Response details are for operator tooling, not public probes.
- `GET /api/csrf` establishes browser CSRF credentials before unsafe requests. Browser code uses `sessionFetch` and `apiUrl`; `sessionFetch` bootstraps CSRF automatically before the first unsafe request.
- Preview `POST identity.signOut` sends the current memory-backed session and CSRF headers for server revocation, then clears the local credentials at dispatch without waiting for that response. Late responses from before the clear cannot restore credentials. Local clearing does not guarantee server revocation; standard deployments still rely on server revocation and HttpOnly cookie clearing.
- `deriveSessionCsrfToken(sessionId: string, csrfSecret: string): string` (`server/security/csrf.ts`) is shared with identity. On issue or rotation, identity calls `SessionTransport.issue({ token, csrfToken: deriveSessionCsrfToken(sessionId, csrfSecret), absoluteExpiresAt })`; logout invokes `clear()`. Server-side identity resolution precedes validation of `x-rp-csrf`.
- `sendPrivateDownload(res: Response, payload: { stream: Readable; filename: string; contentType: string; size?: number }): Promise<void>` (`server/http/downloads.ts`) streams a private attachment. Authorize and durably audit before invoking it. If already committed and the stream fails, the connection is closed rather than framing an additional JSON response.
- `AnalyticsCspPolicy` (`server/security/headers.ts`) admits only `{ scriptSrc?: readonly string[]; connectSrc?: readonly string[] }`. Integration API `services.integrations.analyticsCsp(pathname): Promise<AnalyticsCspPolicy | null>` must return null for disabled providers and private/sensitive routes. HTTP independently limits this to unauthenticated GET navigations to `/privacy` and `/terms`, rejects malformed sources, and never uses redirect, query or origin headers to choose the policy. This hook does not make those paths indexable.
- Signed integration `POST` routes mount from `registerSignedIntegrationWebhooks(router, services)` below `/api/integrations/webhooks`; the router receives up to 256 KiB of raw `application/json` without content decompression. These routes do not resolve cookie identity or use browser CSRF. Each handler must verify provider signature, freshness and replay policy before any effects; skip registration entirely for unsupported routes.
- Before body parsing or session lookup, requests that reach the application pipeline pass a process-local gate of 120 requests per 10-second fixed window per address bucket (`edge_requests`). When the static root is configured, canonical GET/HEAD requests for flat content-hashed `/assets` files, `/fonts` fonts, and `/brand` images use a separate 900-request bucket (`edge_static`). Both use fixed-size counters. API, tRPC, sign-in and credential budgets are unchanged. Probes and credentialless preview CORS preflights bypass the local gate and do not resolve sessions. Canonical browser origin validation and applicable durable edge budgets also precede session lookup; session-bound CSRF remains after lookup.
- `createRateLimiter({ db, clock, logger, settings, tokenHashKey }): DbRateLimiter` (`server/security/rateLimiter.ts`) implements core `MaintainableRateLimiter` and `cleanup(): Promise<number>`. `limiter.registerMaintenance(jobs)` registers job type `http.rate_limit.cleanup`. Database schema export: `rateLimitCounters`.
- Address subjects use IPv4 (including IPv4-mapped IPv6) or the IPv6 /64; limiter normalization does not truncate the request context address. Durable slots use HMAC with an HKDF-derived subkey of `tokenHashKey`, shared by replicas. Deploy the new mapping together across replicas; old subject-to-slot assignments are not carried forward and old rows expire normally. Rotating the root changes the mapping again.
- `http.rate_limit.<category>` settings accept `{ maxRequests: integer, windowSeconds: integer }`, bounded at runtime. Standard browsing alone fails open with an operational alert on limiter storage failure; API and sensitive categories fail closed. No category may be disabled.
- Browser edge denials emit `http.origin.denied` and `http.csrf.denied` using best-effort notes, sampled once per kind per address bucket per minute per process. Procedure-level rate refusals emit a note under the same sampling policy (`http.rate_limited`, with the registered procedure name and category), including when a tRPC batch partly succeeds. Request logs and sampled Protection events identify the edge bucket or applicable durable category as `rateLimitBucket`; an adapter-owned 429 without edge category metadata is labeled `unclassified`. These logs include correlation IDs and a fixed route template, never original URLs, request payloads, headers, IP addresses or bearer material.

## Increment 04 isolated raw routers

Owners export `(services: Services) => Router`. Routes inside the router are relative to the fixed mount prefix. Use `Router({ caseSensitive: true, strict: true })`; HTTP owns registration, parsing, and policy, and modules must not mount body parsers or CORS middleware. These are not browser-session routes: they never receive portal session identity or a CSRF exception usable elsewhere.

| Slot | Mount prefix | Factory | Methods / body | Authentication |
| --- | --- | --- | --- | --- |
| H | `/api/v1` | `createPublicApiHttpRouter` from `server/modules/publicApi/http.ts` | GET, HEAD, POST, PUT, PATCH, DELETE; optional raw JSON, 256 KiB | Module verifies service key/scopes, optional signature and replay; only named OpenAPI document may be public |
| I | `/api/webhooks/inbound` | `createInboundWebhooksHttpRouter` from `server/modules/integrations/webhooks/http.ts` | POST only; raw JSON, 256 KiB | Module verifies signature, freshness and event deduplication before parsing or effects |
| K webhook | `/api/payments/webhooks` | `createPaymentWebhooksHttpRouter` from `server/modules/payments/http.ts` | POST only; raw JSON, 256 KiB | Module verifies provider signature, freshness and deduplication before parsing or effects |
| K return | `/api/payments/return` | `createPaymentReturnHttpRouter` from `server/modules/payments/http.ts` | GET only; no body | Untrusted browser navigation; no authority to transition payments or disclose state. Redirect only to reviewed, fixed same-origin paths |

HTTP validates host and runs address admission, protection and a durable IP budget first. Request correlation is available via `getRequestContext()`. Raw bytes are supplied in `req.body` as a `Buffer` when nonempty; absence represents empty bytes and is rejected by the webhook mount. HTTP does not decompress or parse JSON in these branches. Service API routes additionally own per-key rate limits and problem-details responses. Malformed framing and oversized bodies can be refused before module authentication. Unhandled requests under a registered prefix terminate there with 404; they do not fall through to browser routes or the SPA. No new CORS grants. Preview accepts neither unsafe cross-origin browser credentials nor production raw callbacks. Provider webhooks and returns are restricted to the canonical host; proxy aliases may not redirect them with query material. These slots do not change the existing integration webhooks or OAuth callbacks.
