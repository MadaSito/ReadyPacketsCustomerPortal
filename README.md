# ReadyPackets Portal

Self-hosted customer portal, staff workspace and administration console for ReadyPackets
(`https://my.readypackets.com`). It is a secure rebuild from the specifications in `docs/source-specs/`, with local
sign-in and mandatory MFA, a modular TypeScript monolith (Node 22, Express, tRPC, React, MySQL 8.4) and no runtime
dependency on any hosted AI or SaaS service.

Status and verification evidence are tracked in `docs/application-context/`, `docs/verification/` and each module's
`VERIFICATION.md`. Nothing in this repository should be read as a certification, a guarantee of security, or a
WCAG/ADA conformance claim.

## Quick start

### Prerequisites

- Node.js `>=22.12 <23` and pnpm `12.21.0` (`packageManager` in `package.json`).
- MySQL 8.4 and the matching `mysql` and `mysqldump` client tools (needed by backups and the backup tests).
- Linux or macOS. Production targets Ubuntu 24.04 LTS.

### Local development

```bash
pnpm install --frozen-lockfile

# Configuration comes from the process environment only; there is no .env loader.
# Copy the variable names from server/config/env.example (REQUIRED ones are marked) into your shell or a
# secret manager, using synthetic values. Keys are generated, never invented:
pnpm tsx scripts/ops/keys/generate.ts --out-dir ./.secrets   # writes 0600 files, prints NAME_FILE=… lines
pnpm tsx scripts/ops/keys/doctor.ts                          # checks names and rules, never prints values

pnpm db:migrate          # forward-only migrations from ./migrations (DATABASE_URL or DATABASE_URL_FILE)
pnpm admin:create --email admin@example.test --name "Local Admin"   # first administrator; password via hidden prompt
pnpm seed:demo           # optional: synthetic demo data, never for production

pnpm dev                 # API + worker (RP_ROLE=all) with reload
pnpm dev:client          # Vite dev server for the client
```

`pnpm db:migrate` needs a committed `migrations/` directory (generated by `pnpm db:generate`). If it is missing from
your checkout, the migration step and the CI migration-drift check fail until the baseline is committed.

### Checks and builds

| Command | What it does |
| --- | --- |
| `pnpm typecheck` / `pnpm lint` | TypeScript (no emit) and ESLint |
| `pnpm test`, `pnpm test:server`, `pnpm test:client` | Vitest (server tests need MySQL) |
| `pnpm build` | Client (Vite) and server bundle into `dist/` |
| `pnpm build:preview` | Sandboxed preview build (synthetic data only; never production) |
| `pnpm start` | Run `dist/server/main.js` |
| `pnpm ops:migrate`, `pnpm ops:admin-create` | Bundled operator commands from `dist/ops/` (production hosts) |
| `pnpm db:generate` | Generate a migration from schema changes |
| `pnpm verify` | typecheck + lint + test + build |

In the shared engineering sandbox, use `scripts/dev/{tc,test,lint,commit,add-dep}.sh` as described in the
[build contract](docs/engineering/BUILD_CONTRACT.md).

### Production install

Use the reviewed release kit, not the dev commands:

```bash
sudo bash deploy/install.sh <REVIEWED_FULL_COMMIT_SHA>    # native Ubuntu 24.04 profile (Nginx + systemd)
sudo bash deploy/upgrade.sh <CANDIDATE_FULL_COMMIT_SHA>   # drained, backed-up, forward-only upgrade
sudo bash deploy/uninstall.sh                             # deactivates; never deletes data or keys
```

A Docker Compose profile is in `deploy/docker/`. Operator tools are in `scripts/ops/`:
`keys/` (generate, rotate, doctor), `backup/` (run and verify encrypted backups), `restore/` (isolated restore drill),
`install/` (VPS install, upgrade and rollback helpers), `migrate.ts`, `create-admin.ts` and `seed-demo.ts`.
Read [Install on Ubuntu 24.04](docs/operations/INSTALL.md) and [release gates](deploy/VERIFICATION.md) first.
