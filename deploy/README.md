# ReadyPackets deployment

For a fresh Ubuntu 26.04 LTS server, start with the [automatic installation guide](../docs/operations/AUTO_INSTALL.md). From a reviewed clone made as root with `umask 022`, run `sudo bash deploy/auto-install.sh --domain my.readypackets.com --acme-email you@example.com`. Replace the host and contact address with yours. The installer sets up dependencies, adds swap as needed by default and saves initial administrator credentials in `/root/readypackets-initial-admin.txt`. It displays the temporary password once on the controlling terminal (or with `--print-credentials` when no terminal is attached).

For Ubuntu 24.04 or a manually provisioned Ubuntu 26.04 host, use the [manual runbook](../docs/operations/INSTALL.md) and `install.sh`. The kit renders the Nginx edge and TLS snippets and portal site from `/etc/readypackets/site.conf`; the host name and alias are fixed after installation, but the automatic installer can switch certificate modes. `upgrade.sh` re-renders those files and reloads Nginx before reopening traffic; the native-install workflow does not exercise upgrades. `uninstall.sh` removes the managed Nginx site, snippets and renewal hook but leaves data, certificates and swap. Review the [verification gates](VERIFICATION.md) before admitting customer data.

A self-contained Docker Compose stack for evaluation and testing under any host name is in [`docker/`](docker/README.md) (`install-vps.sh` and `rp-docker.sh`). It is checked end to end by the `container` workflow and is not a substitute for the native kit: it has no backups, drain or rollback. The earlier Docker draft and the separate archive installer were removed. Do not enable the legacy example `nginx/my.readypackets.com.conf` alongside the managed site.

Release promotion (`prepare-release.mjs`) includes `dist/ops/catalog-import.js` and `data/catalog/**` (`readypackets-offerings-v3.0.json` and `offerings.schema.json`) in each published `/opt/readypackets/releases/<commit>` tree while continuing to exclude `seed-demo.js`. `auto-install.sh` loads the offerings unless `--skip-catalog` is given. With `install.sh` alone, use the [manual catalog import](../docs/operations/INSTALL.md#load-the-offerings-catalog-optional) after migration and first-administrator bootstrap.
