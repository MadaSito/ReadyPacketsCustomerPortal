# Native Ubuntu deployment verification

Scope: the native single-node install, upgrade, and deactivation for `my.readypackets.com`. The earlier Docker draft and duplicate archive installer were removed; the alternate legacy Nginx example is not covered. The evaluation Docker Compose stack in `deploy/docker/` is verified separately by `.github/workflows/container.yml` (see `deploy/docker/README.md`, "How it is verified") and is outside this document.

## Completed static checks

- **Syntax**: `bash -n` on `install.sh`, `upgrade.sh`, `uninstall.sh`, and `lib.sh`; `node --check` on the release and credential helpers.
- **Release promotion fixture**: Imported synthetic build output owned by an unprivileged UID and separate root-owned manifest/migration inputs into a fresh root-owned staging directory; verified metadata, mode/owner, and exclusion of the seed bundle. An unexpected symlink was refused before release metadata was written. No dependency build or live release was used.
- **DSN policy fixture**: Eleven checks covered the loopback spellings, including local resolution for `localhost`, required TLS for non-loopback backups and all runtime/migrator connections, and refusal of fragments, repeated TLS mode, control characters in credentials, and unsupported socket options. These checks validate parser policy, not a TLS handshake.
- **Bundled operator entry points**: Plain Node 22 loaded all seven installed operator bundles with an empty environment and no input. Each returned its usage or configuration error without contacting MySQL or writing keys. These smoke checks used the workspace dependencies, not a staged production-only install.
- **Systemd offline parse**: Assembled the exact `10-runtime.conf` drop-in layout in a temporary directory. `systemd-analyze verify` accepted the two app services with intrinsic unprivileged identities, the `cli` and `pre_upgrade` backup instances, and the timer using an isolated unit search path with generators disabled. The sandbox analyzer is systemd 259, not the Ubuntu 24.04 target's running manager.
- **Diff hygiene**: Checked the package and runbook for whitespace errors with Git.
- **App contract cross-check**: Compared Nginx matches and limits to the mounted file, portable and presentation upload routes, Express JSON and signed-webhook limits, forwarding to the exact trusted loopback peer, app-generated IDs/HSTS, and application-controlled asset cache headers. Compared stop handling to the HTTP close and worker drain implementation, and traced backup CLI credentials and child-process privileges.

## Preconditions and unresolved gaps

- **Migration artifact**: At review time the checkout contained no tracked `migrations/meta/_journal.json` or migration SQL. The package explicitly stops before activation if the reviewed release lacks that material. Generate, review, commit, and test the actual migration set before production use.
- **MySQL account separation**: Runtime is schema-scoped DML, not database-enforced append-only. The app uses the same pool for runtime audit operations and retention deletes. The read-mostly backup account has scoped ledger writes and by default requires SSL. Confirm that the release's dump/import binaries enforce verified TLS and that the dump excludes triggers, events, and routines before deploying the revised grant. Confirm the approved loopback exception is denied for other hosts and no extra global privileges are needed.
- **Issuer**: [Let's Encrypt has ended its OCSP service](https://letsencrypt.org/2025/08/06/ocsp-service-has-reached-end-of-life.html). The production example ships with stapling disabled for that issuer. Settings for a compatible alternate CA are provided but were not verified.

## Not verified here

- **Host lifecycle**: No installer, upgrader, uninstaller, production dependency installation, migration or restore was executed. ShellCheck is unavailable. On an Ubuntu 24.04 staging VM, prove first run and interrupted retries, the hoisted and pruned dependency build (no links in the promoted tree), plain Node commands after dev dependency removal, denial of key reads by the build identity, effective systemd credential isolation, power-loss recovery, and data retention across deactivation.
- **Nginx/TLS and services**: Nginx was unavailable, and no systemd service was launched. Run `nginx -t` and test real TLS versions, rejects, ACME renewal, alias redirect, rate limiting, forwarding, upload streaming, headers/logging, credential ownership, private temp, system call compatibility, timeouts, and both probes. Validate port 5000 is loopback-only and the app process honors the exact single-proxy trust rule. Test the 90-second stop path and rejection of unproved worker suspension.
- **Data plane**: Grants and backup options were inspected, not applied to MySQL 8.4. Test account privilege denial and allowed operations, the exact `mysqldump` flags and required privileges, successful archive verification, off-host recovery, an isolated restore, and cutover to a compatible old release. Health checks are not a worker liveness, backup, or restoration test.
- **End-user and integrations**: DNS, firewall, customer browser behavior, first sign-in/MFA, SMTP, SIEM listener authentication/receipts, and real load/backpressure were not tested.
