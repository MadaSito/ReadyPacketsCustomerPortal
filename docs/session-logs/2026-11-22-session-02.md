## Prompt 21

> 1. Workflows should be able to be exported individually or select flows or all and able to be imported to
>    another ReadyPackets Portal
> 2. Add the ability to upsell in the cart
> 3. Add a discount code system for orders that the admin can give out codes or links with expiration and
>    other controls to minimize abuse
> 4. Add a policy acceptance log center that tracks the customer's acceptance of the policy and any policy
>    updates. it should also show on the customers profile in the admin portal

### Response

Increment 05 planned on branch `feat/increment-05`. Decisions D1–D4, packages, ports and the definition of
done are in `docs/engineering/INCREMENT_05_CONTRACT.md`. New capabilities: `workflows.export`,
`workflows.import`, `carts.upsells.manage`, `promotions.read`, `promotions.manage`,
`policies.acceptances.read`, `policies.acceptances.export`.

### Results

Delivered on branch `feat/increment-05` and merged through a pull request (see the repository history).

- **Workflow export and import** — `/admin/workflows`: export one, selected or all workflows as an
  integrity-checked JSON package; import with preview, per-workflow choice (create, add as draft, skip),
  policy mapping and step-up. Imports are drafts only. Setting `orders.workflow_transfer.enabled`, off by
  default. ADR 0042.
- **Cart suggestions (upsell)** — `/admin/carts/suggestions` and the customer cart: add-on, tier-upgrade
  and automatic bundle-completion suggestions, at most three, server-priced, never added without the
  customer's action. Flag `feature.cart.upsell`, off by default. ADR 0043.
- **Discount codes and links** — `/admin/promotions`, `/promo`: percentage or fixed codes, scope, dates,
  total and per-customer limits, first-order-only, customer and e-mail-domain allow-lists, single-use
  batches, pause / revoke, redemption log and CSV exports, a per-order ceiling (default 50 %), rate limits
  and a temporary pause after repeated failures, links that keep the code out of URLs sent to servers.
  Flag `feature.promotions`, off by default. ADR 0044.
- **Policy acceptance log centre** — `/admin/policy-acceptances` (Log, Coverage, Policy updates, exact
  version text, CSV export) and a "Policies" tab on the admin customer profile. Always on, read-only.
  ADR 0045.
- Migration `0005_increment_05` (additive: 8 tables, 9 columns).

Decisions taken without the owner and to be confirmed: imports never publish; a code and the bundle
discount do not add up unless the code allows it (the larger applies); the per-order ceiling of 50 %; a
redemption stays used after a refund and is released only for a cancelled order on which nothing was paid
and no online payment was ever started; API v1 does not accept codes; staff may read the acceptance log
and codes list, administrators manage them; automations are not part of a workflow package; discount codes
and cart suggestions are not part of the whole-data portable transfer.

Verification: see "Verification for increment 05" in `docs/application-context/STATUS.md` for what the
integrator ran, what was reported by the team only, and what was not verified. Defects found and fixed in
the integrator's browser pass: a 5 px overflow at 320 px on the cart suggestions list; "Showing 1 discount
codes / redemptions" wording.

Note: the engineering team ran out of credits near the end of the increment; the integrator completed
verification, documentation and release alone.
