# Session 01 (2026-11-21): Native automatic Ubuntu installation

## Prompt 7 (owner)

> can you create an auto install script for a native install on ubuntu 26.04 LTS? I will make the repo public during the install then make it private when its done installing. Also make sure there is a defauly admin account that is created and the username and password shown at the end of the install

## Prompt 8 (owner)

> make sure all the prereqs are installed automatically as well with the option to select the portal public domain address

## Response and actions

1. Added a native auto-installer for dedicated Ubuntu 26.04 LTS servers. It installs prerequisites, builds the reviewed local Git commit, configures loopback MySQL 8.4, sets up a chosen canonical DNS name and optional redirect alias, and supports public ACME or self-signed TLS. Repository access is needed for the clone or later fetch, not for the running portal; the guide describes using a read-only deploy key instead of making the repository public.
2. Added initial local administrator bootstrap with a generated temporary password. The installer shows `Portal address`, `Sign-in name` and `Password` at the end, with a root-only copy under `/root`. First sign-in requires a new password and authenticator enrollment. The bundled offerings are loaded by default.
3. Added a native install workflow covering disposable Ubuntu runners, with separate self-signed and local ACME paths, credential masking and checks for repeat installs. Updated the automatic and manual runbooks with operator steps, file locations, troubleshooting, and limits.

## Files

- `deploy/auto-install.sh`, `deploy/lib.sh`, `deploy/install.sh` and `deploy/nginx/*.conf.template`: automatic and manual host setup, site rendering and administrator bootstrap.
- `.github/workflows/native-install.yml`, `scripts/ci/native-install-{prepare,run,smoke}.sh`: runner preparation, installer checks and smoke checks.
- `docs/operations/AUTO_INSTALL.md`, `docs/operations/INSTALL.md`, `deploy/README.md` and `README.md`: deployment documentation; related updates in the changelog, SDLC, requirements register and application context.
