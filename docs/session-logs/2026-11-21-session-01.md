# Session 01 (2026-11-21): Native automatic Ubuntu installation

## Prompt 7 (owner)

> can you create an auto install script for a native install on ubuntu 26.04 LTS? I will make the repo public during the install then make it private when its done installing. Also make sure there is a defauly admin account that is created and the username and password shown at the end of the install

## Prompt 8 (owner)

> make sure all the prereqs are installed automatically as well with the option to select the portal public domain address

## Response and actions

1. Added a native auto-installer for dedicated Ubuntu 26.04 LTS servers. It checks root custody of the checkout, can add a persistent 2 GB swap file, installs prerequisites and builds the reviewed local Git commit. It configures loopback MySQL 8.4 and serves the chosen host and optional redirect alias through Nginx. The names stay fixed after installation; certificate mode can change. Certbot is only installed for public TLS, with Ubuntu's `universe` enabled if needed. Repository access is needed for the clone or later fetch, not for the running portal.
2. Added local administrator bootstrap with a generated temporary password stored in `/root/readypackets-initial-admin.txt`. `Portal address`, `Sign-in name` and `Password` are shown once on the controlling terminal; without a terminal they are printed only with `--print-credentials`. Later runs refer to the saved file rather than showing the password again. First sign-in requires a new password and authenticator enrollment. The bundled offerings are loaded by default.
3. Updated the manual and automatic runbooks for the shared deployment lock, Nginx edge and TLS snippets, native upgrade and deactivation, and off-server copies of the backups and secrets.
4. Defined three `native-install` jobs on GitHub-hosted Ubuntu 26.04 runners: x64 self-signed without alias; arm64 self-signed with alias and `--swap yes`; and x64 local Pebble ACME on a runner prepared without `universe`, with renewal and certificate-mode switching. The workflow does not exercise native upgrade or uninstall or use the live Let's Encrypt service.

## Files

- `deploy/auto-install.sh`, `deploy/lib.sh`, `deploy/install.sh`, `deploy/upgrade.sh`, `deploy/uninstall.sh` and `deploy/nginx/*.conf.template`: automatic and manual host setup, site rendering, administrator bootstrap and lifecycle operations.
- `.github/workflows/native-install.yml`, `scripts/ci/native-install-{prepare,run,smoke}.sh`: runner preparation, installer checks and smoke checks.
- `docs/operations/AUTO_INSTALL.md`, `docs/operations/INSTALL.md`, `deploy/README.md` and `README.md`: deployment documentation; related updates in the changelog, SDLC, requirements register and application context.
