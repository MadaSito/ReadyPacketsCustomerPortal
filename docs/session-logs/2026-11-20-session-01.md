What the first runs found, and what was done:

1. **Backup tests failed only on the runner** (`MYSQLDUMP_FAILED`, 6 tests). The hosted runner ships the
   MySQL 8.0 client, while the backup module is written for the 8.4 tools that `docs/operations/INSTALL.md`
   requires. The tests job now installs the Oracle MySQL 8.4 client from the vendor repository after
   checking the signing key fingerprint, and asserts `mysqldump` reports 8.4. No application code changed.
2. **gitleaks, 21 findings**: all synthetic fixtures or prose (see step 3 above); recorded in
   `.gitleaksignore` by exact fingerprint.
3. **CodeQL** could not upload results: GitHub code scanning is not available on this private repository.
   The analysis itself ran. The workflow now keeps the SARIF file as an artifact and fails the job on any
   finding with security-severity 7.0 or higher (`scripts/ci/sarif-gate.mjs`); upload is switched on by the
   repository variable `CODE_SCANNING_ENABLED=true`. The gate reported 9 findings, 7 of them high:
   - fixed: four check-then-use file races (offline restore, backup verification CLI, key-file writer, one
     test). Archive paths are now opened first without following symlinks and the opened descriptor is
     inspected (`server/modules/backup/archiveFile.ts`, with tests for symlink, directory, named pipe and
     missing path); key files rely on exclusive create alone.
   - fixed: ticket-number suffix used a modulo on random bytes (no actual bias with a 32-character alphabet,
     replaced by `randomInt` anyway).
   - accepted after review, with written justification in `.github/codeql-baseline.json`: "insufficient
     password hash" on the backup manifest checksum (it hashes a manifest that carries only a key identifier,
     not a password) and "missing rate limiting" on the application shell (rate limited by the admission
     middleware, which CodeQL does not model).
   - left as notes (severity 4.0, below the gate): two "overly large range" reports on the syslog SD-ID

5. **A real defect surfaced as a one-off CI failure** on commit `c1664a7`: a freshly generated key was

   new installation could (rarely) have refused to start. Short tokens are now screened only in values that
   are not well-formed high-entropy keys; a regression test builds keys containing those tokens and fails
   without the fix (`server/config/env.ts`, `server/config/env.test.ts`).
6. **Dependabot** opened PR #1 (`@types/node` 22 to 26). The runtime is pinned to Node 22, so major updates

### Response and result (prompt 5)

Not deployed. The portal is a long-running Node server plus a separate background worker, and it needs
MySQL 8.4 and private file storage on disk. Vercel runs short-lived functions without a persistent process,

services. The Vercel connection was not used. The owner's next prompt asked for a server or container

### Actions (prompt 6)

1. `deploy/docker/Dockerfile`: two-stage build on a digest-pinned Node 22 image, mirroring the native
   release recipe (frozen lockfile, hoisted production-only dependencies, no demo seed, no package manager
   in the runtime image, unprivileged uid 10001).
2. `deploy/docker/compose.yaml`: `init` (generates passwords, a private database CA and certificate, and
   the application keys, once) → `db-perms` → `db` (MySQL 8.4, TLS required, internal network only) →
   `migrate` → `web` + `worker` → `caddy` (ports 80/443, automatic certificate). Read-only root file
   systems, all capabilities dropped, no secrets in environment variables or arguments.
3. `deploy/docker/rp-docker.sh` (up, admin, catalog, status, logs, down, destroy) and
   `deploy/docker/install-vps.sh` (installs Docker from the signed repository after checking the key
   fingerprint, pre-flight checks, then `rp-docker.sh up`).
4. `.github/workflows/container.yml` and `scripts/ci/container-smoke.sh`: build the image and exercise the
   whole stack on a GitHub-hosted runner; a second job runs the Docker installation step on clean
   Ubuntu 24.04, Ubuntu 22.04 and Debian 12 images.
5. Two read-only peer reviews (operations and HTTP edge). No Critical findings. Fixed from them: updates
   now stop the portal before migrations run; `init` refuses to start when a secret volume is missing; the
   web process listens only on its proxy-network address and the worker moved to its own outbound network;
   the proxy error log no longer carries request targets or headers; upload allowances match only the exact
   case-sensitive routes; Host headers with another port are refused; the build context is limited to the
   files the image needs; program files are not group-writable; the Docker pre-flight checks Engine 23+,
   Compose and Buildx and never replaces an existing Docker.
   Not adopted, with reason: per-read upstream timers in Caddy (a local test showed they also count the
   client's upload time and cut uploads short; whole-request budgets are used instead); `.env` stays mode
   0644 because it holds no secret.
6. The first pull request in this repository showed that the CodeQL gate failed on every pull request:
   CodeQL limits pull request results to the changed lines, so an accepted finding elsewhere was missing
   from the output and the gate reported its baseline entry as stale. The gate now lists such entries
   without failing on pull requests (`SARIF_GATE_PARTIAL`); the full analysis on `main` still enforces them.
7. Documentation: `deploy/docker/README.md` (new), `deploy/README.md`, `deploy/VERIFICATION.md`, `README.md`,
   `docs/operations/INSTALL.md`, application context and status, requirements register rows PI-01, MP-2.4,
