### Task 2 — Phase I (P101) on a synthetic order (integrator's own run)

The reference documents give the payload but no webhook address, and the dispatcher only sends to public
HTTPS destinations on port 443 that match an outbound allow-list rule (loopback can never be allowed). The
portal side was therefore exercised against a neutral public echo service, `postman-echo.com`. **This is
not the owner's production pipeline and no production run was started.**

1. Integrations, Outbound connections: rule added for `postman-echo.com:443`, purpose "Webhook", HTTPS,
   with a reason (step-up).
2. Integrations, Production pipeline: canon version `ReadyPackets_Production_v2.0`, run mode
   `production`, P101 and P201 URLs on the echo host, pipeline enabled. "Test Phase I (P101) destination"
   (a dry run that sends nothing) returned `DRY_RUN_ALLOWED`: matched the rule, resolved to public
   addresses only.
3. Order `RP-2026-000006`, tab "Automation": the payload preview showed exactly the ten documented fields.
   "Start Phase I" was confirmed with the release label `preview_synthetic_p101_echo_test`.
4. Result: one dispatch, state "Delivered", HTTP 200, attempt 1 of 5, reason `PRODUCTION_DELIVERED`,
   idempotency key `rp-prod:p101:<dispatch id>`. Audit events `integration.production.dispatch.requested`
   (administrator) and `integration.production.dispatch.delivered` (worker, with the dispatch correlation
   reference). The dispatch is listed on the order and on the Production pipeline page, and in "Order
   history".
5. Payload sent (synthetic values):

   ```json
   {
     "customer_id": "RPCUS-JFME6CB3B",
     "order_id": "RP-2026-000006",
     "packet": "1",
     "tier": "Basic",
     "canon_version": "ReadyPackets_Production_v2.0",
     "run_mode": "production",
     "client_name": "Riley Referred (synthetic)",
     "client_email": "demo.referred.1@example.com",
     "release_status": "preview_synthetic_p101_echo_test",
     "bundle_scope_manifest": "{\"packet_1\":\"Basic\"}"
   }
   ```

   The SHA-256 the portal stored for the request body equals the SHA-256 of this document serialised in
   this field order, so the bytes that left the portal are known. `bundle_scope_manifest` is a JSON
   string, not an object, and `order_scope_mode` is not sent, as the reference documents require.
6. After Phase I was delivered the Phase II card changed to "Ready after artifact check" with the payload
   `{customer_id, order_id, run_mode}` copied from the Phase I record. Phase II was **not** started.
7. The pipeline switch was turned off again afterwards so that nothing else can be sent to the echo
   service. The saved URLs and the allow-list rule remain in the preview and should be replaced by the
   real ones.

Not verified: the real P101 receiver (authentication header, its response, de-duplication on retry), any
downstream artifact, and Phase II. "Delivered" only means the configured endpoint answered with HTTP 2xx.

### Observations not changed in this session

- A person who abandons authenticator setup and signs in again in a **new session** within ten minutes is
  told "An authenticator setup is already in progress. Try again after it expires." The message does not
  say how long. With cookie sessions a page reload keeps the session, so this needs a sign-out, another
  browser or another device; in the preview (in-memory sessions) any reload triggers it.
- "Order history" labels the two pipeline events "Integration production dispatch requested / delivered";
  a friendlier label is missing.
- The `…dispatch.requested` audit event carries request and trace identifiers but not the dispatch
  correlation reference; the delivery events do.
- In the preview the refund tab still showed the old balance about five seconds after a refund was
  recorded; a fresh visit showed "Refunded" and a zero balance. Not investigated; the same screen updated
  without a reload in the development profile on 2026-11-21.
- In the preview a verification link requested within 60 seconds of the previous one is not issued (resend
  cooldown), so the demo link only appears on a later "Send a new link".
