### Decisions

- Fix pack 07.2 is on branch `fix/increment-07-2`.
- There is no database migration. Every new value is stored in the existing settings or columns.
- The upgrade commands are unchanged.
- The cause of point 2 on the owner's server could not be confirmed. We had no access to the server's logs, and a real Stripe account cannot be tested here. So the fix makes every failure visible and recoverable, and adds a probe that catches the likely causes before customers meet them.

### Response and results, per point

**1. The update message** (`1be1cc2`).
- **What it is.** The prompt appears when the server has been updated but this browser tab still runs the previous version of the web app.
- **Old copy.** "A new version of ReadyPackets is available. Reload to update; unsaved form input on this page will be lost."
- **New copy.** The title is "ReadyPackets was updated on the server". The body is "This tab is still running the previous version. Reload switches to the new version; you stay signed in, but unsaved input on this page is lost. Later keeps the previous version in this tab until you reload."
- **Behaviour.**
  - **Later** hides the prompt only until the next in-app navigation, so a stale tab is reminded.
  - The update is never applied automatically, because a reload would drop unsaved input.
  - Below medium width, the prompt sits above the phone tab bar.

**2. No redirect to Stripe after placing an order** (`c082b4e`, `53786b0`).
- **Cause on the owner's server: not confirmed.**
- **Changes in checkout:**
  - after the order and invoice are committed, a failure to start payment now returns a typed `payment_unavailable` result, never a silent fall-through;
  - the customer sees "Your order … is placed, but we could not open the secure payment page", with the order, invoice and **Pay now**;
  - the browser's allowlist for the redirect address now matches the server's (`https://checkout.stripe.com` only);
  - the return and cancel pages tell "awaiting payment" apart from "pending confirmation", and offer **Pay now**.
- **Changes in payments:**
  - every Stripe Checkout Session failure gets a specific reason code;
  - the audit event `payments.attempt.failed` carries sanitised diagnostics;
  - an operational alert, "Customers cannot reach Stripe Checkout", is raised;
  - `/admin/payments/setup` has a status banner (**ACTIVE** / **NOT ACTIVE**, with what customers experience and the missing gates) and shows the **Last checkout-session failure**;
  - a new **Verify Checkout session creation** probe creates an unpaid session and expires it at once;
  - the restricted-key permissions are documented.
- **Operator steps.** These are in the [Admin guide](../guides/ADMIN_GUIDE.md#getting-card-checkout-active-increment-072).

**3. Invoice and receipt branding, and the order and project** (`8d20507`, `8a9901b`, `fdd5583`).
- **Branded PDFs.** Invoice, payment receipt and refund note PDFs are branded: logo, wordmark, tagline, legal name, brand colours and a footer with page numbers.
- **Order and project.**
  - An **Order** and **Project** block is near the top of page 1.
  - The pages and lists show an "Order & project" card and columns.
  - The invoice and receipt e-mails include Order and Project.
- **Characters.** A WinAnsi encoding fix means characters such as `·`, `–` and curly quotes now print correctly.
- **Existing documents.**
  - Invoices render on demand, so existing invoices pick up the branding.
  - Receipt and refund note PDFs stored before the upgrade keep their original file (integrity hash), while the pages and e-mails show the order and project.
- **Where to edit.** `/admin/invoices` → **Company profile** has the legal name, tax ID, address, contact, logo and payment instructions. `/admin/payments` has the **Receipt footer note**.
- **PDF accessibility.** PDF/UA is not claimed.

**4. "Signing secret is not in the correct format"** (`53786b0`).
- **Likely cause** (inferred from the screenshot, not confirmed): a longer value that did not start with `whsec_` was in **Primary**, while the 38-character `whsec_` secret was in **Secondary**.
- **Changes:**
  - pasted values are normalised (quotes, backticks, invisible characters, wrapped lines);
  - each field gets its own error that names what was pasted (`pk_…`, `sk_…`/`rk_…`, `we_…`, masked, too short, too long) without echoing it;
  - each field has a show/hide control and settings that stop autofill;
  - hints say where in Stripe to copy each value;
  - the difference between Primary and Secondary is explained.

**5. Setting the default order workflow** (`4fb93be`).
- **Where.** `/admin/workflows` shows the default workflow and offers **Set as default** on any published workflow.
- **Checks.** It needs fresh verification (step-up), and is audited as `workflow.default.changed`.
- **Effect.** New orders use the new default's latest published version. Existing orders keep their version.
