## Prompt 35

Verbatim. The owner attached one screenshot of the terminal, which is not stored in the repository.

> I typed the Backup-Verified incorrectly now i cant get it to run even when reentering the upgrade script. give me the instructions to fix this now and if i run into this issue again

While upgrading to the increment 08 release, the owner mistyped the `BACKUP-VERIFIED` confirmation, so `deploy/upgrade.sh` stopped with "confirmation did not match". It then refused to start again while the maintenance flag and the state file existed.

### Result

Recovery instructions were given in five steps, chosen by the `phase=` value in `/etc/readypackets/upgrade-state`:

1. Read the state file as data (`sudo cat /etc/readypackets/upgrade-state`).
2. **`phase=draining` or `phase=backup`.** No migration has run and the old release is still current. Start the services while traffic is fenced and check `/readyz`.
3. Re-enable the services, and the backup timer only if `backup_timer_enabled=yes`.
4. Remove the maintenance flag and the state file.
5. Run the upgrade again and type the confirmations exactly.

For `phase=migration_started` or `phase=verifying`, the answer was not to roll back, and to follow §6 of [UPGRADE.md](../operations/UPGRADE.md). The same guidance is now a "Mistyped confirmation" box in §6 of [UPGRADE.md](../operations/UPGRADE.md#6-recovery-if-an-upgrade-stops-mid-way) (increment 09).

No code changed for this prompt.
