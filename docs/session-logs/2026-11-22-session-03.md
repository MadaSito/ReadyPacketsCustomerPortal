### 2. Authenticator setup no longer locks

Cause: a staged authenticator setup lives for ten minutes and belongs to the sign-in that started it. A
second sign-in of the same account was refused with "An authenticator setup is already in progress", and a
setup that had expired on an open page kept answering "that code didn't match".

Change ([ADR 0046](../adr/0046-authenticator-setup-supersede.md)):

- a new sign-in gets a new QR code at once; the earlier setup is discarded, is never shown again and the
  replacement is audited as `auth.totp.enrollment_superseded`;
- confirming an expired or replaced setup is refused with `TOTP_SETUP_EXPIRED` or `TOTP_SETUP_REPLACED`
  before the code is examined, and audited as `auth.totp.enrollment_denied`;
- the setup page then shows a new QR code, clears the code field and moves focus to a message that says
  what happened and what to do; it also states that the QR code works for 10 minutes.

Files: `server/modules/assurance/factors.ts`, `client/src/features/auth/pages/MfaEnrolPage.tsx`, tests in
`server/modules/assurance/assurance.test.ts` and `client/src/features/auth/auth.test.tsx`, documentation
(`CHANGELOG.md`, `docs/guides/CUSTOMER_GUIDE.md`, `server/modules/assurance/API.md`,
`docs/security/REVIEW-audit-coverage.md`).
