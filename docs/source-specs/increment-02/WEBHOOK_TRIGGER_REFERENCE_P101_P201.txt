             ReadyPackets Webhook Trigger Reference
                            Phase I Start Webhook (P101) and Phase II Start Webhook (P201)


Purpose
This document defines the exact trigger payload information for the ReadyPackets Phase I and Phase II manual
webhooks using the supplied Packet 7, mixed-tier, multi-packet example. It is limited to the parameters shown below and
does not define any additional packets, tiers, scenarios, or webhook fields.
Controlling rule: the Phase II payload must reuse the same customer_id, order_id, and run_mode used in the Phase
I payload for the same order. A mismatch creates a different order path or fails to continue the intended run.


Quick Sequence
      Step     Action                          Payload / Scenario                          Do not proceed until

      1        Trigger Phase I start.          P101 Phase I webhook payload.               Phase I final artifacts exist for the same
                                                                                           order_id.

      2        Trigger Phase II start.         P201 Phase II webhook payload using the     Phase II and downstream phases are
                                               same customer_id, order_id, and run_mode.   allowed to continue automatically.


For the example in this document, the order_id is dev-phasei-v11-test-028. If a new test run is created, update the
order_id consistently in both P101 and P201. Do not update one payload without updating the other.

Packet 7 / Multi-Packet Detail From the Supplied Payload
The supplied Phase I payload expresses Packet 7 as a mixed-tier, multi-packet partial order. The fields work together and
should be treated as a coordinated set for this example.

     Field group                  Configured value                          Meaning for this trigger

     packet + tier                packet = "7"; tier = "Mixed"              The outer order is Packet 7 and is labeled Mixed because
                                                                            the included packet tiers are defined individually in the
                                                                            bundle_scope_manifest.

     order_scope_mode             multi_packet_partial                      The order is not documenting a complete all-packet bundle. It
                                                                            is a multi-packet partial selection.

     bundle_scope_manifest        {"packet_1":"Standard","packet_2":"Basi   This run includes packet_1 as Standard and packet_2 as
                                  c"}                                       Basic.



Important formatting rule for bundle_scope_manifest
Inside the outer JSON, bundle_scope_manifest is not a nested JSON object. It is an escaped JSON string. This is why the
value contains backslashes before the quotation marks around packet_1, Standard, packet_2, and Basic.
"bundle_scope_manifest": "{\"packet_1\":\"Standard\",\"packet_2\":\"Basic\"}"


Wrong format to avoid
Do not send bundle_scope_manifest as a raw object unless the receiving scenario has been explicitly rebuilt to
expect a nested object.
"bundle_scope_manifest": {"packet_1":"Standard","packet_2":"Basic"}

Phase II Webhook - P201
Use this payload only after Phase I for the same order has completed and the Phase I output artifacts exist. The Phase II
payload is intentionally much simpler and must match the Phase I identity fields.
{
    "customer_id": "dev-001",
    "order_id": "dev-phasei-v11-test-028",
    "run_mode": "production"
}

Phase II Start Rule
Trigger P201 only after the Phase I folder for the same order contains the expected Phase I final artifacts. The known
Phase I artifact set for the passing workflow was four files in Final_Merge: Phase1A_Merged.txt,
Phase1B_Adjudication.json, Phase1B_DeepResearch_Evidence.txt, and PhaseI_InterviewGuidance.txt.
Do not send P201 just because P101 ran. Send P201 after the Phase I outputs exist for the same customer_id and
order_id.

Pre-Trigger and Post-Trigger Checklist
  Checkpoint                   Required verification

  Before P101                  Confirm the order_id is the new intended run ID. For this document: dev-phasei-v11-test-028.

  Before P101                  Confirm packet = "7", tier = "Mixed", order_scope_mode = "multi_packet_partial", and bundle_scope_manifest
                               is an escaped JSON string.

  After P101                   Confirm Phase I output artifacts exist for the same order_id before starting Phase II.

  Before P201                  Confirm customer_id, order_id, and run_mode exactly match the P101 payload.

  After P201                   Let downstream scenarios continue automatically. Do not manually trigger later phases unless debugging
                               requires it.

  Failure prevention           Do not mix order IDs across phases. Do not use 026 in P201 if P101 used 028.




Minimal pass indication for this trigger chain
A clean run should produce Phase I artifacts, advance through Phase II automatically after P201, create downstream
Phase III/Phase IV outputs, and leave no active PENDING_RETRY row in P5_DLQ for the same order_id. This document
does not define downstream payload contracts; it only documents the Phase I and Phase II trigger parameters supplied
above.
