# ReadyPackets platform and portable contract security review

Reviewed the platform module, environment and field crypto, and the independent portable contract, CLI, and legacy adapter. This is a point-in-time read-only review of the checkout at `8cc944c` and nearby in-progress module code, not an assertion about a deployed installation. No Critical or High findings were verified; the review identified **9 Medium, 3 Low**, and one first-run operational gap.

## Platform

- **P1 · Medium · Image storage admission and commit handling:** `server/modules/platform/presentation.ts:143–157,197–200,220–231` checks active-image capacity before the guarded transaction, so distinct administrators can both pass the same quota check. Soft deletion in this service does not reclaim bytes, and a transaction error triggers unconditional object deletion even when the server could have committed before the connection failed to acknowledge it. Serialize quota reservation on one durable lock or counter, check capacity in the transaction, and reconcile staged storage objects against durable metadata before cleanup. Have retention retire unreferenced objects with an audited workflow, not an immediate delete based on a transaction exception.
- **P2 · Medium · Synchronous config KDF blocks other requests:** `server/modules/platform/configTransfer.ts:76–78,142–154,198–213` calls `scryptSync` in request handling, with up to two derivations for a secret-bearing document. The routes use the `expensive` budget, but `server/trpc/trpc.ts:169–176` keys it by session for authenticated requests; it is not a process-wide KDF concurrency budget. Use asynchronous derivation with a bounded queue and a process-wide execution budget to keep ordinary requests responsive.
- **P3 · Medium · Rotation updates are not atomic with audit:** `server/modules/platform/reencrypt.ts:45–65,87–116` performs row rewrites and a checkpoint update before the separate audit write. Audit failure can leave durable changes with no corresponding batch record; concurrent batches starting from the same cursor can also overwrite a newer cursor with an older one. Lock the checkpoint for one bounded batch, use the same transaction for compare-and-set writes, checkpoint, and durable audit, and verify that an audit failure rolls them back together.
- **P4 · Low · Branding validation does not ensure valid, stripped images:** `server/modules/platform/imageValidation.ts:99–109,130–150` leaves the JPEG tail after the first Start of Scan unexamined, so later metadata is not stripped. A WebP extended header can also satisfy the dimension check without an actual image frame. This is a malformed-content or metadata-retention issue, not evidence of script execution. Decode with compressed-byte, pixel, frame, and resource limits and re-encode without metadata; if retaining a structural check, validate the complete container and require a frame.
- **P5 · Medium · Config export lacks live actor reauthorization:** `server/modules/platform/router.ts:86–101` passes a live guard for apply but not export; `server/modules/platform/configTransfer.ts:127–181` reads values, prepares the document, and audits without rechecking the actor. Revocation during export therefore does not prevent release. Secrets are returned only as passphrase-encrypted content, not plaintext, but a requesting administrator supplies that passphrase. Export eligibility defaults to true (`server/modules/platform/settingsRegistry.ts:124–145`); SMTP and Stripe definitions observed in working integration code rely on the default (`server/modules/integrations/settings.ts:225–232,298–322`). Use a short guarded transaction for the data snapshot, finish the expensive derivation outside it, then reauthorize and write the export audit together before releasing the document. Prefer explicit secret export eligibility.

## Portable contract and CLI

- **C1 · Medium · Default pre-authentication KDF cost is too broad:** `portable/src/limits.ts:38–40` and `portable/src/crypto/envelope.ts:64–81,199–205` allow \(N=2^{20}, r=16, p=4\) under independent caps before header MAC verification. The scrypt working-set term \(128Nr\) is about 2 GiB at those limits, with higher compute cost at the permitted parallelization setting. This concerns the independent CLI and default library; `server/modules/portable/transferPolicy.ts:16–29` already uses lower caps. Default to aggregate memory and work ceilings close to the writer profile, and require operator opt-in for higher resource budgets.
- **C2 · Medium · Ambiguous extension inventory loses verified evidence:** `portable/src/reader.ts:188–210,295–321,400–405` does not reject duplicate logical extension names or file references. Multiple declarations can pass inventory, digest, and schema verification, but held-evidence reads use the first matching name. Require unique extension names and paths and a canonical mapping from the declared name to its path before accepting the manifest.
- **C3 · Medium · Regenerated legacy records do not keep their portable IDs:** `portable/src/legacy/adapter.ts:124–129` supplies package `generatedAt` as the timestamp component of each derived record ID; `portable/src/ulid.ts:18–36` encodes it directly. An unchanged source record therefore receives a different ID when exported again at a different time, weakening ID-based reconciliation and leaving downstream natural-key checks to catch duplicates. Use only stable inputs for record IDs and version the change with an explicit reconciliation plan for previously imported IDs. Package IDs can remain distinct from record IDs.
- **C4 · Low · CLI status and extraction do not match their advertised meaning:** `portable/cli/verify.ts:11–12,40–45,138–146` maps report-level unsupported requirements and `ARCHIVE_INVALID` to generic failure despite the documented unsupported/archive categories. Extraction (`:163–186`) omits held extensions and writes normalized records alongside a manifest with source digests, so success does not mean a complete, independently re-verifiable source extraction. Align the exit contract and distinguish source evidence from transformed output. Preserve held evidence in a lossless mode, or clearly label omissions and generate new digests for a projected output.
- **C5 · Medium · Held extension exclusion check does not cover all accepted nesting:** `portable/src/contract/exclusions.ts:60–87` silently stops at the traversal depth cap, and `portable/src/reader.ts:304–313,400–405` applies that scanner to opaque extensions without rejecting over-depth JSON. Core records separately have a depth check (`portable/src/validate.ts:15–18`), but a verified extension can retain data beyond the scanner's coverage. Reject extensions that exceed a bounded depth/node budget before scanning. Treat opaque evidence and heuristic secret scanning as distinct from strong data classification.
- **C6 · Low · The reported ciphertext digest can refer to different bytes than verification:** `portable/src/reader.ts:46–56,78–104` hashes the file and later decrypts it, then checks only that its length did not change. A same-length local modification can separate the reported identity from the authenticated bytes; the portal's private temporary copy narrows exposure. Hash the exact bytes consumed during authenticated header/body reads, or verify a private immutable snapshot, and handle partial reads and writes.
- **C7 · Medium · Legacy conversions do not fully honor caller resource limits:** `portable/src/reader.ts:69–74` caps the whole legacy envelope, and `portable/src/legacy/adapter.ts:142–149,286–296,393–421` applies a fixed source record cap and some shared per-record validation but does not enforce caller-specified `maxRecordsPerType`, `maxObjectBytes`, or `maxTotalUncompressed`. A constrained consumer can consequently accept a converted package outside its resource policy even though it remains inside the legacy envelope cap. Validate counts and anticipated decoded sizes before materializing files and account for aggregate decoded data under the configured limits.

## Verified boundaries and release notes

- **Field crypto and settings:** `server/config/env.ts:73–95,343–359` validates decoded key lengths, limits the data keyring, and rejects duplicate decoded keys across configured roles. `server/security/fieldCrypto.ts` uses authenticated encryption with random IVs and requires AAD; the settings store binds secrets to the setting key and returns only `configured` in secret descriptions (`server/modules/platform/settingsStore.ts:204–217,284–306`). Ordinary exposed setting and flag mutations pass a live transaction guard and write audit in that transaction (`server/modules/platform/router.ts:41–67`, `server/modules/platform/settingsStore.ts:133–179`).
- **Setup, schema, and public health:** `server/modules/platform/router.ts:30–31,70–71` exposes setup status as a read, not a provisioning write; `server/modules/platform/module.ts:228–234,259` checks administrator presence and directs operators to a server-side command. `package.json:101` names `scripts/ops/create-admin.ts`, which was absent from the reviewed tracked checkout. Treat this as a first-run release blocker, not evidence of public takeover. Ship the host-only provisioning entry point with atomic first-admin checks, durable audit, and mandatory MFA enrollment. `server/http/app.ts:313–321` exposes boolean health/readiness only; detailed health requires staff access and capability. The schema check compares the release and applied migration ledgers by hash, time, and length (`server/modules/platform/schemaContract.ts:61–95`); it is not live DDL drift verification.
- **Package encryption and extraction:** The v3 reader authenticates the canonical header and indexed chunks with authenticated finalization before opening the ZIP (`portable/src/crypto/envelope.ts`, `portable/src/reader.ts:78–104`). ZIP names are allowlisted, duplicates and special entries are rejected, and aggregate and per-entry size/ratio controls apply (`portable/src/archive/zip.ts:44–89`). CLI record and object destinations are built from validated types and digest names, not arbitrary member paths (`portable/cli/verify.ts:168–184`). Authentication does not establish sender identity, freshness, or prohibit replay of a whole intact archive; importer replay tracking and source trust are separate policy controls.
- **Legacy trust boundary:** `portable/src/legacy/adapter.ts:58–97,124–149,286–296,441–465` uses fixed scrypt parameters, binds the legacy format as AEAD AAD, recomputes the legacy package digest, checks decoded file size and hash, and gates iteration through verification. Its normalized provenance is a representation of input claims, not external proof of authorship. Successful independent verification does not establish that the target is suitable for live activation.

## Re-review · 2026-11-20

Independently inspected portable remediation `23b3aba` and platform remediation `208f124`. Ten of the original twelve findings are closed at those revisions. P1 and C7 remain open in part. “Closed” refers to the original finding, not to broader assurance of the component.

### Platform findings

- **P1 · Open in part:** The singleton slides-row lock now serializes quota admission and normal soft deletion triggers object cleanup. The image suite passed, including cleanup on audit rollback. The ambiguous-commit path still treats an ordinary non-locking lookup that sees no row as proof of absence, even if the first connection's transaction is still resolving (`server/modules/platform/presentation.ts:200–209`). Retain staged bytes on ambiguous outcomes until reconciliation can prove no durable reference. The sweep (`:279–289`) has no caller in reviewed server code and repeatedly selects only the newest soft-deleted rows, without a completion marker or advancing cursor; add a scheduled, durable and fair retry mechanism.
- **P2 · Closed:** `server/modules/platform/configTransfer.ts:80–102` uses asynchronous scrypt with one active operation and up to four queued derivations. The config-transfer suite passed its round-trip and wrong-passphrase cases; the queue bound and event-loop behavior were checked by inspection, not a load test. A separate compatibility note appears below.
- **P3 · Closed:** `server/modules/platform/reencrypt.ts` locks the batch checkpoint and performs CAS writes, checkpoint advance, and audit in one transaction. The re-encryption suite passed audit rollback and concurrent runner checks.
- **P4 · Closed for the reported parser defects:** The image suite passed checks for metadata between JPEG scans and after EOI, plus the required still WebP frame and RIFF rebuild (`server/modules/platform/imageValidation.ts`). Full pixel decode and re-encoding are still outside this structural validation.
- **P5 · Closed:** Export now receives a live actor guard, checks it before reading settings, and checks it again in the transaction containing the export audit without holding that transaction across scrypt (`server/modules/platform/configTransfer.ts:151–215`). The config-transfer test exercises guard refusal and absence of successful audit; it also confirms default secret export is now opt-in.

### Portable findings

- **C1 · Closed:** The aggregate KDF ceilings are checked before derivation in `portable/src/crypto/envelope.ts`; the tamper suite confirms rejection of aggregate out-of-budget parameters, and the round-trip suite confirms the normal writer profile still works.
- **C2 · Closed:** `portable/src/reader.ts` rejects repeated names and noncanonical extension/record paths before evidence reads. The CLI/policy suite passed duplicate/noncanonical inventory coverage.
- **C3 · Closed for regenerated exports:** `portable/src/legacy/adapter.ts:148–155` uses a fixed epoch instead of the export timestamp for record IDs; the legacy test compares IDs across distinct generated dates. A prior deployment of the old derivation, if any, would still need explicit reconciliation of old IDs.
- **C4 · Closed:** The CLI documents archive verification failure separately from local I/O, reports unsupported-only requirements as exit 4, and writes verified v3 members verbatim, including held extensions. Inspection and the CLI/policy suite confirm the new status and extraction behavior. Legacy extraction is explicitly labeled as reconstruction.
- **C5 · Closed:** The reader rejects overly deep optional extension JSON, and the exclusion walker fails closed at its own traversal cap. The CLI/policy suite passed the over-depth extension check.
- **C6 · Closed:** The reader hashes header, MAC, and body bytes from the same authentication/decryption pass (`portable/src/reader.ts:66–95`); tamper and round-trip tests compare that digest with the ciphertext digest. This does not guarantee immutability of the caller's source path.
- **C7 · Open in part:** The legacy suite passed basic limit refusal, and the adapter now checks top-level input counts and estimates file sizes before decoding. `portable/src/legacy/adapter.ts:31–47,138–144,281–309` still does not apply `maxRecordsPerType` to expanded normalized record types or include converted metadata in `maxTotalUncompressed`. Apply bounded accounting to every normalized record type and both metadata and objects, and cover nested-only and metadata-only input in tests.

### Bootstrap and additional observations

- **First-admin command:** The host-only `scripts/ops/create-admin.ts` now exists in the working tree. It checks migration compatibility and delegates account creation and audit to transactional identity provisioning, with password change and MFA enrollment required. The identity suite passed concurrent bootstrap, refusal with an existing active admin, rollback on audit failure, and enrollment checks. The missing implementation is resolved in the worktree, but inclusion in the release and an end-to-end CLI run were not verified.
- **Bootstrap password file · Low, open at review:** `scripts/ops/create-admin.ts:50–53` directly reads the supplied path without enforcing the documented restrictive permissions, owner, regular-file type, or size limits. Use a bounded descriptor-based secret reader that checks the actual opened file, preserves password whitespace apart from the final newline, and does not log the path or content.
- **Legacy file handle · Low, open at review:** The successful legacy return at `portable/src/reader.ts:57–62` bypasses the explicit close at `:92` and the error handler. The passing legacy suite emitted Node file-descriptor garbage collection warnings. Close the source handle on all exit paths.
- **Config document compatibility · Follow-up:** `server/modules/platform/configTransfer.ts:235–238` rejects the different salts written by the former secret export path without changing the format version. If those exports were distributed, support them through the same bounded async KDF or version the new format and provide migration guidance. No deployed historical exports were verified.
