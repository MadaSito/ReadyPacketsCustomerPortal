# 0048 — Installable app (PWA) for Apple, Android, Windows and desktop

Status: Accepted (2026-11-23; implemented in increment 06 and checked in the lead's QA browser run — see STATUS.md. Assumptions below remain open for owner confirmation)

## Context
The owner asked for the portal to be installable on Apple, Android, Windows and other devices, before native apps exist. [ADR 0020](0020-delivery-scope-mobile-and-integrations.md) made the portal an installable PWA, but the install path was hard to find, and iOS needs manual steps.

## Decision
- **Manifest:**
  - `id`, `name`, `short_name`, `description`, `start_url`, `scope`, `lang`, `dir` and categories;
  - `display: standalone` with `display_override`;
  - theme and background colours for both themes;
  - shortcuts to Orders, Create an order, Messages and Support.
- **Icons and meta tags:**
  - icons at 192 and 512 px, both `any` and `maskable`;
  - an Apple touch icon at 180 px;
  - Windows tiles as far as the manifest covers them;
  - `apple-mobile-web-app-*` and `theme-color` meta tags;
  - safe-area insets.
- **Install entry.** An **Install app** entry sits in the account menu and the sign-in page footer.
  - Chromium browsers (Android, Windows, ChromeOS and desktop) use `beforeinstallprompt`.
  - iOS and iPadOS Safari get step-by-step instructions: Share → Add to Home Screen.
  - macOS Safari gets the same: Add to Dock.
  - The entry is hidden when the portal already runs installed (`display-mode: standalone`). It can be dismissed, and the choice is remembered on the device.
- **Service worker (zero trust):**
  - it precaches only an allowlisted set of public static files, fetched without credentials;
  - every other browser request goes to the network only: there is no private runtime cache and no background sync;
  - `/api`, `/trpc`, attachments and downloads are excluded;
  - signing out clears the runtime caches;
  - the public offline page is shown for an eligible navigation only when the network fails;
  - the update prompt remains.

  A test covers the route rules.
- **Server:**
  - nginx sends `Service-Worker-Allowed`;
  - `sw.js` and the manifest are not given long cache lifetimes.
- **Native readiness.** A future Android or iOS app can reuse API v1, the local sign-in and MFA flows (once a mobile token strategy has been reviewed) and the deep-link paths. `assetlinks.json` and `apple-app-site-association` are **not** published until an app exists. No native app is built in this increment.

## Assumptions to confirm with the owner
- The install prompt is on by default.
- The shortcut set (Orders, Create an order, Messages, Support) is the owner's choice to change.

## Consequences
- The portal can be installed from the browser on the platforms above. On iOS the user still follows Safari's own steps; no web page can install itself there.
- Offline use is limited to the offline page. Orders, files and messages always need a network, by design.
