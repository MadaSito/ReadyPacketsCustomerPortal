# Increment 06 accessibility review

This is a scoped review of the Increment 06 changes, not a WCAG conformance finding. Record rendered evidence against the final integrated build, including role, route, state, browser, viewport, theme, and interaction method.

| Changed surface | Evidence and follow-up |
| --- | --- |
| D1: side panel accent | Check rendered contrast, visible focus and selected-route cues, including in forced colours and without relying on the accent. |
| D2: audio recording on orders | In `RecordingPreflight`, the focused microphone-test control can be replaced as the state advances; Files owner asked to keep or recover focus and add a test. Verify the desktop fallback and native audio controls by keyboard in Chromium and Safari, and with permission refused. |
| D3–D5: upsells, PWA, discount limits | Check keyboard operation and focus recovery when an offer disappears; visible and spoken names should identify the specific offer and amount. Verify that install instructions and offline/update notices are understandable and that on-screen discount limits or refusals are announced and linked to the relevant field. |
| D7: protection, sign-in/MFA notices, incident audit | Check named filter/rule controls and loading, no-results and pagination status. When an Unban or Release action removes a row, verify focus returns to the results heading or another useful control. Security owner notified. Verify incident detail is usable as text without relying on colour or a chart. Check that retry status is not read every second and that the expired state is announced once. |
| D8 and D10: phase tasks and workflow transfer | Run conditional fields, permissions or unavailable state, validation, save and cancel, action selection across steps, and focus return. Recheck workflow transfer in each newly exposed route; the previous increment's tests are useful but are not evidence for those mounts. |
| D9 and D12: document import, WYSIWYG and policy-update notices | Check the file label, keyboard reachability of editor toolbar and editor, PDF text-only warning before confirmation, import errors, and a clear post-import focus target. A component test covers confirmation staying bound to the reviewed notice revision after a refresh. In browser, check countdown announcements, audience count, nested step-up and focus recovery when actions disappear, plus scheduled, cancelled, queueing, and completed states. |
| D6: reports | Source includes chart summaries and a data-table equivalent. In browser, check line/bar/pie with multiple series, legend and pattern readability, narrow results and filter reflow, empty/error/retry, and keyboard/assistive-tech access to the data-table alternative. |
| D11: acceptance evidence | Recheck admin evidence and customer receipt with both match/Not matched status and the actor-visible redaction wording. Verify dialog naming, exact text and table associations, focus return and non-colour status; an earlier increment's evidence is not sufficient for newly changed states. |
| D13: warning, remediation and End sessions now | Five D13 component checks passed, including both-theme axe for the exact-version remediation form. Keyboard tests enter the dialog, move focus to policy review, close by Escape, require consent, focus a missing signature, and recover focus after exact-version submission. A coverage test verifies the named End sessions now action and explicit confirmation. Still verify both signed-in shells, the real remediation route and modal stacking in browser; check typed and untyped policies, later/decline, countdown announcements, affected count, and focus after ending sessions. |
| D14–D15: MNDA and receipts | Exercise blocked order creation, order work and payment/receipt paths using keyboard only. Check current-version policy links, error messages and focus recovery when the gate clears. Verify receipt link purpose, download/email progress, and whether equivalent acceptance details remain available as HTML. |

The component runs used synthetic fixtures and jsdom. They do not verify visual focus rings, target dimensions, reflow, rendered colour contrast, reduced motion, prompts from device/browser chrome or spoken output from assistive technologies. No peer browser or server was available during this review; use the integrator's rendered run for separate evidence and list any untested states explicitly.
