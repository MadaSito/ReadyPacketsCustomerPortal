# Increment 04 Part B: acceptance, order workspace and isolation review

This is the Package Y review record for the order workspace. `Not checked` means no independent evidence was collected, not that the feature passed. Use synthetic accounts and records on the assembled local test system. Never use live payment, delivery, storage or identity providers for these checks.

## Accessibility and browser evidence

- **Pages and panels**: Run the shared `pageA11y` helper in light and dark on the assembled order view for new tabs, including Order history, Automation with stage actions, Refund, Acceptances, and File/SharePoint sync. Include the customer gate and printable receipt. Check one visible page heading and main landmark; scan open dialogs in the full document, including portals.
- **Dialogs**: Test accessible name/description, focus on open, tab containment, Escape and focus return to the actual launcher. Confirm the destructive button remains unavailable until the exact typed phrase and all required fields are valid; error and pending states remain perceivable without relying on color. Include Rename, Refund, Redeliver and gate-signing controls.
- **Tab strip**: Check one labelled `tablist` and one selected tab, correct roving focus, Left/Right and Home/End, stable URL and selected-panel relationship, understandable overflow controls, and an accessible compact control below 480 px. Check keyboard traversal into the panel and back out without traps.
- **Browser and manual**: The authorized browser owner records exact route, role, state, theme and viewport at 1440, 390 and 320 CSS px. Component axe is not proof of contrast, reflow, zoom, screen-reader behavior or actual print output. Record incomplete and unverified cases as such.
