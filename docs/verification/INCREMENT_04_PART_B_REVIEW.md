# Increment 04 Part B: acceptance, order workspace and isolation review

This is the Package Y review record for the order workspace. `Not checked` means no independent evidence was collected, not that the feature passed. Use synthetic accounts and records on the assembled local test system. Never use live payment, delivery, storage or identity providers for these checks.

## Security checks

| Scope | Required evidence | Status |
| --- | --- | --- |
| Acceptance text and identity | Verify that the service derives the acting user from the current session, resolves the bound order/workflow/gate/policy, and verifies the digest of exactly the text it presented. It must not trust a posted customer ID, policy text, timestamp, address, agent, or earlier receipt as proof. Validate checkbox and typed-name modes. | Assembled test recomputed the displayed-text SHA-256, confirmed wrong-hash refusal, and checked typed-name and checkbox evidence. |
| Append-only and replay | Repeat and parallel submissions cannot create duplicate evidence. Acceptance for one order, actor, gate, policy or version does not satisfy another. Verify unchanged evidence against a newer policy version, both with and without reacceptance configured. Check version changes between display and submit. | Parallel same-user submissions returned one receipt; another order remained gated. A general policy acceptance did not satisfy the order gate. Admin could complete the same step without evidence. |
| Owner and shared access | A fully enrolled owner can read a gated order. A writable collaborator can read and accept for themselves but cannot use the owner's acceptance to satisfy their gate. A viewer cannot get write access by accepting; an unrelated customer cannot read or alter gate or acceptance evidence. Revocation still applies after acceptance. | Assembled contributor before/after acceptance and after revocation, viewer after acceptance, and out-of-scope receipt checks passed. Broader isolation run pending. |

## Accessibility and browser evidence

- **Pages and panels**: Run the shared `pageA11y` helper in light and dark on the assembled order view for new tabs, including Order history, Automation with stage actions, Refund, Acceptances, and File/SharePoint sync. Include the customer gate and printable receipt. Check one visible page heading and main landmark; scan open dialogs in the full document, including portals.
- **Dialogs**: Test accessible name/description, focus on open, tab containment, Escape and focus return to the actual launcher. Confirm the destructive button remains unavailable until the exact typed phrase and all required fields are valid; error and pending states remain perceivable without relying on color. Include Rename, Refund, Redeliver and gate-signing controls.
- **Tab strip**: Check one labelled `tablist` and one selected tab, correct roving focus, Left/Right and Home/End, stable URL and selected-panel relationship, understandable overflow controls, and an accessible compact control below 480 px. Check keyboard traversal into the panel and back out without traps.
- **Browser and manual**: The authorized browser owner records exact route, role, state, theme and viewport at 1440, 390 and 320 CSS px. Component axe is not proof of contrast, reflow, zoom, screen-reader behavior or actual print output. Record incomplete and unverified cases as such.

| V: Policy audience must be enforced by the gateway | Initial gateway policy lookup checked publication and active status, but did not check whether the document's audience permitted customers. A policy attached to an existing workflow can be reclassified after that workflow is published. | Independently retested: a previously accepted policy reclassified as staff-only was omitted and the gateway blocked.
