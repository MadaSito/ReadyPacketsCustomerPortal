# Increment 04 Part B: acceptance, order workspace and isolation review

This is the Package Y review record for the order workspace. `Not checked` means no independent evidence was collected, not that the feature passed. Use synthetic accounts and records on the assembled local test system. Never use live payment, delivery, storage or identity providers for these checks.

## Security checks

| Scope | Required evidence | Status |
| --- | --- | --- |
| Acceptance text and identity | Verify that the service derives the acting user from the current session, resolves the bound order/workflow/gate/policy, and verifies the digest of exactly the text it presented. It must not trust a posted customer ID, policy text, timestamp, address, agent, or earlier receipt as proof. Validate checkbox and typed-name modes. | Not checked |
| Append-only and replay | Repeat and parallel submissions cannot create duplicate evidence. Acceptance for one order, actor, gate, policy or version does not satisfy another. Verify unchanged evidence against a newer policy version, both with and without reacceptance configured. Check version changes between display and submit. | Not checked |
| Owner and shared access | A fully enrolled owner can read a gated order. A writable collaborator can read and accept for themselves but cannot use the owner's acceptance to satisfy their gate. A viewer cannot get write access by accepting; an unrelated customer cannot read or alter gate or acceptance evidence. Revocation still applies after acceptance. | Not checked |
| Customer write enforcement | Verify HTTP 409 with `CONFLICT` / `ORDER_ACCEPTANCE_REQUIRED` before any persisted or external effect for file upload (default and workflow slot), recording upload, intake draft save and submit, and phase submission. Verify after-accept success for the same user. Run applicable secondary paths such as staged/superseding files, read-only grants, and existing order acknowledgements/transitions separately. | Not checked |
| API v1 | The public API uses a separate order-transition service. A correctly authorized write cannot complete a gated submission without the order owner's acceptance; fail closed if that evidence is missing. Verify authorization, owner and gate selection, and status update in a consistent transaction. Do not count an API request rejected by authentication, schema validation, or a non-gate requirement as gate coverage. | Not checked |
| Receipts and evidence output | Owner and console receive only their permitted receipt/evidence fields. Shared access must not expose other signers' evidence unless explicitly permitted. Source addresses are encrypted at rest and visible only under `sessions.read_all`; customer views must omit them. Check PDF/print routes or direct data endpoints separately from client hiding. | Not checked |
| Rename | Verify `orders.rename` for staff/admin and denial for customer and shared-access roles; existing customer `orders.update` keeps its documented scope. Check stale version, normalization, empty/overlong/control-character input, audit old/new names, unchanged reference, and exactly one history row for a successful rename. | Not checked |
| History | Verify order scoping, stable pagination and category filtering. Seed a staff event with recognizable synthetic name, email, and address. Customer rows, filters, cursors and serialized output must not expose those values or internal metadata; show `ReadyPackets staff` only for permitted staff activity. Independently check legitimate console visibility. | Not checked |
| New procedures | Preserve the live-router inventory gate for customer-reachable resource inputs. For Part B procedures outside that inventory, verify explicit denied customer calls using real records under synthetic staff/admin fixtures. Use the real order/attempt/refund/acceptance/copy references, required flags and known positive controls. Record an owner role/capability denial separately from a cross-customer ownership denial. | Not checked |

## Accessibility and browser evidence

- **Pages and panels**: Run the shared `pageA11y` helper in light and dark on the assembled order view for new tabs, including Order history, Automation with stage actions, Refund, Acceptances, and File/SharePoint sync. Include the customer gate and printable receipt. Check one visible page heading and main landmark; scan open dialogs in the full document, including portals.
- **Dialogs**: Test accessible name/description, focus on open, tab containment, Escape and focus return to the actual launcher. Confirm the destructive button remains unavailable until the exact typed phrase and all required fields are valid; error and pending states remain perceivable without relying on color. Include Rename, Refund, Redeliver and gate-signing controls.
- **Tab strip**: Check one labelled `tablist` and one selected tab, correct roving focus, Left/Right and Home/End, stable URL and selected-panel relationship, understandable overflow controls, and an accessible compact control below 480 px. Check keyboard traversal into the panel and back out without traps.
- **Browser and manual**: The authorized browser owner records exact route, role, state, theme and viewport at 1440, 390 and 320 CSS px. Component axe is not proof of contrast, reflow, zoom, screen-reader behavior or actual print output. Record incomplete and unverified cases as such.
