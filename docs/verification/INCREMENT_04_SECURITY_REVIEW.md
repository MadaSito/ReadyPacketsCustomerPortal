### Verification required at integration

- **C**: The inspected code defaults to detection, uses bounded literal matchers and proxy-normalized IPs, bounds request-event writes by slots, encrypts event addresses, and emits stable audit labels rather than raw headers, bodies, or query strings. Verify effective API authorization, default versus tuned rate limits, break-glass reset, runtime cleanup after upgraded deployment and operator documentation. Confirm MMDB absence and malformed/forwarded country input do not silently gain trust.
- **D**: Source review confirmed fresh persisted step-up for `sessions.revoke_any`, own-session exclusion, and customer-only maintenance targeting. Independent Session Centre server and Identity security UI suites both passed (22 cases each), including local maintenance, per-request network changes, denied unknown-country behavior and cross-session revocation. Scheduled maintenance execution, paired local/Entra sessions and direct Entra maintenance rejection remain unchecked. Use simulated identities only.
- **J**: The cutover is verified with component mocks, not vendor traffic in Chromium. Check the real browser for off/default with no optional storage or network requests; equal reject prominence; GPC/DNT; separate categories; withdrawal/expiry/version change; reload after taint; and exact anonymous `/privacy` and `/terms` only, without query or fragment. Withdrawal applies locally before teardown or ledger submission; verify ledger delivery during reload and fallbacks when local storage writes are unavailable. Confirm CSP, modal interaction and user/anonymous ledger scopes.

The findings above are source observations reported to the module owners.

- **H**: The real Express adapter is mounted and `e7e8bf0` forwards the server-generated request ID to the engine. The edge regression uses a synthetic API service; engine persistence, production signature, replay, and resource scope need separate verification.
- **I, K**: The default inbound webhook, payment webhook, and payment return adapters are mounted behind strict method, body, and authority gating. The 26-case HTTP suite verifies raw bytes, inbound request-ID correlation, the canonical payment notification target, and a fixed same-origin return. Source confirms payment credentials and attempts are scoped by configured mode and that authoritative fetched payment mode must match the attempt. Full service-level payment verification remains pending.
- **L**: Port source demonstrates rechecking persisted session authority and a server-side pricing helper. No end-to-end cart service was in the checkout at this checkpoint; ownership, atomic checkout, and return/retry behavior need verification.
- **G**: Source shows POST `/hold` is rate limited, normalizes inputs without code lookup, and sets a production Secure, HttpOnly, SameSite Lax cookie. The module’s HTTP and tRPC integration and referral/reward invariant tests were not verified at this checkpoint.
- **M**: Source checks current authority for member operations and only searches visible topics with published posts. As of `9916384`, archived categories remain readable and are listed as archived; new topics, replies, and edits are refused. The independent community suite covers archived-category access and reply refusal.
- **F**: Independent `audio.test.ts` passed (2 cases) with the local FFmpeg binary, including source digest and duration checks. Independent `files.test.ts` passed (23 cases), including one verified derivative, original retention, and shared custody transitions. Same-origin microphone policy is covered by the HTTP suite. Browser recording and deployment sandbox boundaries were not verified in this review.
