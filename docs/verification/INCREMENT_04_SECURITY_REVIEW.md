Findings stay open until the owner supplies the disposition and the relevant regression evidence; missing wiring or live evidence is identified separately. Use severity `High`, `Medium`, `Low`, or `Informational` and statuses `Open`, `Fixed, pending verification`, `Verified`, or `Accepted by lead`.

### Verification required at integration

- **C**: The inspected code defaults to detection, uses bounded literal matchers and proxy-normalized IPs, bounds request-event writes by slots, encrypts event addresses, and emits stable audit labels rather than raw headers, bodies, or query strings. Verify effective API authorization, default versus tuned rate limits, break-glass reset, runtime cleanup after upgraded deployment and operator documentation. Confirm MMDB absence and malformed/forwarded country input do not silently gain trust.
- **D**: Source review confirmed fresh persisted step-up for the `sessions.revoke_any` capability through `authorizeInTx`, own-session exclusion for other-session actions, and customer-only maintenance targeting. Full integration verification remains open for parallel local and Entra sign-in under the same user/policy, per-request network change, configured unknown-country behavior, scheduled customer maintenance and cross-session revocation. Use simulated identities only.
- **J**: Client/provider cutover and real-browser integration remain unverified. Verify off/default with no optional storage or vendor requests; equal prominence for reject; GPC/DNT defaults; separate analytics and replay categories; withdrawal/expiry/version change; actual vendor scope restricted to anonymous exact `/privacy` and `/terms` without query or fragment; and no optional capture on other public pages, notably `/accessibility`. Check that real page/browser CSP, modal interactions, and user/anonymous ledger scopes agree.

The findings above are source observations reported to the module owners.

- **H**: The real Express adapter is mounted and `e7e8bf0` forwards the server-generated request ID to the engine. The edge regression uses a synthetic API service; engine persistence, production signature, replay, and resource scope need separate verification.
- **I, K**: Both peer adapters are now present in the shared checkout. Callback prefixes are reserved with strict method, body, and authority gating. Provider verification needs separate regression evidence.
- **L**: Port source demonstrates rechecking persisted session authority and a server-side pricing helper. No end-to-end cart service was in the checkout at this checkpoint; ownership, atomic checkout, and return/retry behavior need verification.
- **G**: Source shows POST `/hold` is rate limited, normalizes inputs without code lookup, and sets a production Secure, HttpOnly, SameSite Lax cookie. The module’s HTTP and tRPC integration and referral/reward invariant tests were not verified at this checkpoint.
- **M**: Source checks current authority for member operations and only searches visible topics with published posts. Archived categories are filtered from category discovery but readable by ID; new topics and replies are refused, while edits remain possible. Align documentation and tests with the intended archive policy.
- **F**: Independent `audio.test.ts` passed (2 cases) with the local FFmpeg binary, including source digest and duration checks. Independent `files.test.ts` passed (23 cases), including one verified derivative, original retention, and shared custody transitions. Same-origin microphone policy is covered by the HTTP suite. Browser recording and deployment sandbox boundaries were not verified in this review.
